## 一、准确性缺陷修复

### 1.1 未核验草稿不得交付、保存或导出

引用校验、语义核验、证据链与可信度都发生在最终收口阶段。若把模型原始分片先显示出来，
用户会短暂看到稍后被删掉的结论或伪引用；停止时还可能把半截草稿误当成答案。

- 后端只在内存中累计模型草稿，经过 `_finalize_agent_answer()` 后才发送 `verified_delta`；
  正常生成路径不再向浏览器发送 `draft` 或未经核验的 `delta`。
- 手动停止与网络中断统一走 `finishInterrupted()`：清空不完整内容，只显示
  「本轮生成未完成，未展示或保存答案」，且不提供复制、反馈或收藏入口。
- 停止轮次不写入会话历史，也不进入后续追问上下文；旧版本遗留的 `unverified` 轮次在恢复时过滤。
- 因此页面展示、导出、会话恢复与后续模型历史都只接触已经完成最终核验的答案。

### 1.2 多库问答只给模型每库第一块（Codex P1-3）

`_pack_agent` 保底给每库一个席位后直接返回，剩余检索结果全丢。
正确证据若落在某本书的第 2~5 条，模型根本看不到，表现为莫名其妙的假拒答。

保底解决的是"公平"，不是"只给一块"。改为：保底最多占**一半**可用预算、每库上限 320 字符，
其余按全局检索名次补满。

> 首版把整个预算按库数均分给保底块（900÷2=447×2=894，剩余为 0），等于换个形式重现原 bug，
> 已修正。

### 1.3 中文跨语言随机假拒答（Codex P1-2）

语义核验器对跨语言结论要做「翻译 + 蕴含」判断，比同语种难得多；
小模型给出的 `PARTIAL`/`UNSUPPORTED` 一旦偏了，句子被整条裁掉，裁光即退化为拒答。
Codex 已加双语二次核验（先翻译再判断），并对数字/否定/比较/绝对化断言保持 fail-closed。
本轮核实该路径生效，未叠加改动。

### 1.4 逐句裁剪留下代码标识符残句（Codex 中优先级）

复现确认与此前修过的 `[p.2]`、`1.5` 属同一类：`dict.items()` 里的点被当句末，
切成 `Use dict.` + `items() to iterate…`，前半句被裁掉后留下无主语残句。

改为**词内点一律不断句**（小数、代码标识符、模块路径、缩写、版本号），
再补一条「真句子不会以小写字母开头」兜住 `U.S. standard` 这类缩写尾点。
中英文正常断句不受影响（已加测试锁定）。

### 1.5 无效知识库 ID 静默回退（Codex 中优先级）

原实现：请求的库全部失效时**静默改用当前激活库**作答，而答案上的引用看起来完全正常，
用户无从察觉自己问的是 A、系统答的是 B。

改为三档契约：

| 情形 | 行为 |
|---|---|
| 未显式指定库 | 回退到当前激活库（正常默认） |
| 指定了、部分可用 | 用可用的那些，`dropped_libraries` 上报前端提示 |
| 指定了、**全部**不可用 | 抛 `LibraryUnavailable` → 409，**绝不改用别的库作答** |

用 app 层 `exception_handler` 统一收口，保证将来新增端点不会漏掉这条契约；
流式端点响应已开始、发不出状态码，另在生成器内就地转成 `error` 事件。

## 二、竞品能力对标

调研对象：RAGFlow、AnythingLLM、Open WebUI、Dify。取其**核心且与本项目定位相容**
（全本地离线 + 可溯源）的八项，并增加失败诊断与可执行补救：

| # | 能力 | 接口 | 说明 |
|---|---|---|---|
| A | 引用原文片段 | `GET /api/source` | 按库 + 来源 + 页/loc 精确取回命中块，防同名 PDF 串书 |
| B | 自动回归自检 | `POST /api/batch` | 人工关键词才计正式命中率；自动参考答案只作辅助覆盖检查 |
| C | 知识库健康诊断 | `GET /api/library/health` | 页覆盖按全库 metadata 统计；块长与类型用均匀抽样 |
| D | A/B 对比 | `POST /api/compare` | 同题两套配置并排，差异摘要 |
| E | 混合检索 | 问答请求 `hybrid` 开关 | 向量 + 关键词 RRF 融合；小样本收益不稳定，默认关闭 |
| F | PDF 原页渲染与高亮 | `GET /api/source/page` | 回到正确原文件、正确页，并高亮命中片段 |
| G | 页范围限定 | 问答请求 `page_scope` | 只在指定页检索；范围内无依据就拒答，不偷用范围外内容 |
| H | 跨教材概念对照 | `POST /api/concept` | 多库分别取证，再展示共同点、差异与来源 |

低可信或拒答结果会给出原因诊断，并提供「扩大页范围 / 开启混合检索 / 深度重试」等
与诊断匹配的一键补救；补救仍走同一套最终核验和严格拒答边界。

### 关于 C 的一个自查

首版用 `col.get(limit=N)` 取样，那是**插入顺序的前 N 块**——对 PDF 就是目录、版权页
这类天然很短的前置内容，于是「过短块占比」被系统性放大。

| Think Python | 修复前（前 200 块） | 2026-08-11 最终复核 |
|---|---|---|
| 中位块长 | 57 字符 | **415**（均匀抽样 800 / 1441 块） |
| 过短占比 | 79.5% | **30.4%** |
| 页覆盖 | 1–19 页 | **覆盖 239 页（全库 metadata 精确统计）** |

块长改为全库均匀抽样、页覆盖改为全库 metadata 扫描后，工具反而报出真问题：
多模态AIGC讲义 232 页中仅 126 页有内容，
中间有页解析失败。

### 关于 D 的设计

两臂**直接复用 `api_ask`**，一行问答逻辑都不复制——检索、打包、生成、引用校验、
语义核验走逐字节相同的链路，差异只可能来自那一个被测开关。控制变量由代码结构保证，
而不是靠"我说它们相同"。对照时强制清空历史。

实测（Think Python）：

| 场景 | 严格溯源 | 允许教材外补充 |
|---|---|---|
| 库内题 | 引用 1 处全命中 · 有据 5/6 · 接地 60% | **各项完全相同**，仅多 24% token |
| 库外题 | `[NO REFERENCE FOUND]` | **同样拒答** + 单独标注的补充段 |

这组数据本身即可证明：补充不碰溯源部分，两部分的分离是结构性的。
同时补上评委「A/B test，最好和最坏都要展示」那条。

面板内写死诚实边界：*单题一次对照只能展示行为差别，不构成统计结论——
本项目实测噪声底为同配置重跑翻转 0.6–1.5%。*

## 三、可用性修复

- **焦点锁定**：抽屉与移动侧栏加焦点陷阱（记住来源焦点 → 移入面板 → Tab 循环 →
  Esc 关闭 → 焦点归位）。桌面端侧栏常驻可见，按遮罩是否真的显示来判断是否加锁，
  比写死断点更贴合实际布局。
  必须 `stopImmediatePropagation`：页面另有 Escape 处理器，若让同一事件继续分发，
  它会发现"抽屉已关"而顺势去 `stopActiveRequest()`，把正在生成的回答一起停掉。
- **生成测试题与批量自检可停止等待**：接入 `activeRequest` 身份机制，旧请求的迟到回调
  不会覆盖新请求的 busy/停止状态。同步 Ollama 调用可能在服务端完成当前单题，界面会如实提示。
- **停止轮次不保存**：未完成、未核验的内容不进入会话、导出或模型历史，避免污染后续追问。
- **侧栏信息架构重做**：常用 6 项固定展示，低频 7 项收进「更多」；侧栏可折叠，
  左上角按钮可重新打开；修复「更多」菜单被 `aside` overflow 裁剪的问题。
- **资料与状态抽屉**：资料管理、运行状态将原有真实 DOM 节点借入抽屉，关闭后归还，
  不复制第二套状态或事件绑定。
- **会话整理**：会话动态分为「已置顶 / 最近对话」，图钉状态持久化；空分组不占位。
- **响应式收口**：桌面与 375px 移动端均保留问答主路径，移动侧栏和工具抽屉不产生横向溢出。

## 五、已知边界

1. **ollama 服务端 0.32.6，而 v8final 跑在 0.32.3 —— 已按项目规矩跑 250 题回归对齐，
   结论是无真实差异。** 详见 `250题版本回归_20260810.md`：

   | 题型 | 0.32.3 基线 | 0.32.6 本次 | 差 |
   |---|---|---|---|
   | answerable | 111/119 = 93.3% | 111/119 = 93.3% | +0.0pp |
   | unanswerable | 74/75 = 98.7% | 75/75 = **100.0%** | +1.3pp |
   | fuzzy_desc | 19/27 = 70.4% | 19/27 = 70.4% | +0.0pp |
   | fuzzy_kw | 8/29 = 27.6% | 8/29 = 27.6% | +0.0pp |

   逐题翻转仅 **1/250 = 0.4%**，低于项目实测噪声底（同配置重跑 0.6–1.5%），
   且唯一那道是**变对**（Microbiology 的不可答题 `Describe hidden diversity.`
   由误答转为正确拒答）。**不可答题由拒答变作答 0 道**，抗幻觉底线未退。
   编造 0 道、`/api/chat` 降级 0 次、库指纹全部一致。

   因此 v8final 的 4432 题口径在 0.32.6 下**仍然成立**，无需重跑全量。
   注：本回归验的是 CLI 评测路径（`main.py`），由于稳定版与 beta 的 `main.py` 逐字节相同，
   结论可直接用于判断交付口径。
2. **引用页码保证来自实际检索结果，但"每句是否被原文完整蕴含"属更高阶语义审计。**
   系统通过接地率、证据链与可信度显式暴露该风险，不伪装成完全确定。
3. **跨语言作答的逐句接地率无法计算**，此时可信度封顶「中」并注明原因，
   不因"没测过"而给高分。
4. **停止按钮首先保证前端不展示、不保存迟到结果。** 同步 Ollama 调用可能仍在服务端完成当前单题，
   因此停止后立刻发起重任务仍可能短暂共享模型资源。
5. **自动生成的测试题与参考答案不是人工 GT。** 只有明确提供人工关键词的题才进入正式命中率；
   自动参考答案只提供辅助词面覆盖检查，必须人工确认后才能转入正式评测集。
6. **复杂多库回答可能出现“引用合法但部分解释性主张未完全落证”。** 系统以低置信度、
   逐条支持状态和存疑标记暴露该边界，不能把“页码合法”宣传成“每句话都已证明”。
