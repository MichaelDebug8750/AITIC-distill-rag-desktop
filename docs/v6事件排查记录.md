# v6 事件排查记录：一次根因在仓库之外的回归

> 归档日期：2026-07-30
> 事件性质：回归验证不达标 → 四次误判 → 定位真因 → 修复并全量验证
> 方法论价值：这是本项目至今唯一一次**根因不在代码、不在数据、不在配置**，而在外部依赖版本里的故障

---

## 一、起因

`_vl_to_prose`（VL 输出转散句）改动完成后，按既定流程做端到端回归验证。

- **回归集**：Business Ethics / Think Python / Microbiology 三本，共 250 题
- **判据**：可答严格命中率必须回到 v3 基线的 92.4%
- **命令**：`--no-vl` 纯文本模式（`_vl_to_prose` 只作用于 VL 分支，纯文本跑本应与 v3 完全一致）

**实测结果（eval_v6chk）**

| 指标 | v3 基线 | v6chk | 判定 |
|---|---|---|---|
| 可答 | 110/119 = 92.4% | 105/119 = 88.2% | **不达标** |
| 模糊 | 27/56 = 48.2% | 10/56 = 17.9% | **严重退化** |

模糊题掉了 30 个百分点。逐题看，症状极其特征化：

```
Q: cornea blindness condition
v3 答案: Acanthamoeba keratitis can lead to blindness if left untreated. [p.955]
v6 答案: [p.955]
```

模糊题答案剥掉引用标记后，**正文长度中位数为 0**。分题型统计：

| 题型 | 空壳答案占比 |
|---|---|
| answerable | 2.5% |
| fuzzy_kw | 31.0% |
| fuzzy_desc | **59.3%** |
| unanswerable | 0% |

而且 28 道空壳答案里有 12 道 `ok_loose=True`——**页码引对了**。检索是好的，生成端没把内容写出来。

## 二、四次误判

### 误判① 分块逻辑退化

**依据**：前序会话做过 HEADING_RE 窄化（修复①）和 LIST_ITEM_RE（修复②），都导致过类似退化，后已回滚。怀疑回滚不彻底。

**证伪**：给向量库加分块指纹后重建。

```
分块指纹 677d4622f062 | 总块数 1441
```

Think Python 原版 1441 / 修复① 1118 / 修复② 1135。**1441 = v3 原版**，代码侧分块逻辑清白。

### 误判② 向量库陈旧（代码回滚了但库没重建）

**依据**：分块改动活在库里不活在代码里。`--skip-build` 复用旧库时，`.built_book` 标记只校验"这库是哪本书建的"，**不校验"哪版代码建的"**。

**证伪**：用全新库重跑 250 题（eval_v6b）。

| | v6chk | v6b（新库） |
|---|---|---|
| Business Ethics | 47/50, 3/25, 25/25 | 47/50, 3/25, 25/25 |
| 全量可答 | 105/119 | 105/119 |
| 全量模糊 | 10/56 | 10/56 |

**逐题完全一致。** 唯一变化是升配 102→83（闸门默认值归位的效果）。库不是原因。

> 注：此处犯了一个推断错误——拿到 1441 就宣布"结论确定，三条证据闭合"。实际上那三条证据全都只证明了**分块逻辑同源**，一条都没证明**结果可复现**。判据从头到尾只有一个：重跑出来的数字。

### 误判③ 调用路径漂移

**依据**：`_generate()` 有主路径（`ollama.generate` → `/api/generate`）和降级路径（HTTP `/api/chat`）两条，且 `except Exception` 是**静默**降级。会话四记录显示 ollama 0.31 时代 `/api/generate` 收严返 400，当时很可能全程走的降级路径。若 ollama-py 升级后主路径不再抛异常，等于调用模式悄悄换了道。

**证伪**：同一 prompt 打四种模式对照（`diag_modes.py`）。

| 模式 | 输出 |
|---|---|
| A `ollama.generate(think=False)` | `[p.955]`（7 token） |
| B HTTP `/api/chat` + `think:false` | `[p.955]` |
| C HTTP `/api/generate` + `think:false` | `[p.955]` |
| D `think=True, num_predict=900` | `[p.955]` |

**四条路全都只吐标签。** 路径漂移排除。

### 误判④ 不可答探针被污染

**依据**：探针的构造判据是"术语字符串在书里出现 0 次"，验的是字面不是语义。`indirect method`（基底节 indirect pathway）、`latency period`（磁盘延迟）、`tree diagram`（数据结构的树）这类词字面可能确实不出现，但概念真实存在。

**部分证伪**：回原书核对全部编造判定（`verify_fab.py`）。

- 全部 49 道 `exact = 0`——探针的字面判据成立
- 引入「接地率」（答案内容词落在引用页里的比例）后：76% 低接地（<0.3），仅 10% 高接地（≥0.6）
- 低接地样例：Gray's Anatomy p.48 讲的是交感神经到心脏的走行，模型答的是"副交感神经系统起自颅骶部"——**教科书知识，不在那页，引用纯属装饰**

**结论**：探针缺陷只解释约 10%，且 v3 基线同比例（9%），两边对称，不影响结论。

## 三、真因

**决定性证据来自 `diag_raw.py`**——绕过 `_strip_think` / `is_abstain` / `verify_citations` 全部后处理，直接打印 ollama 的原始返回。

```
-- ollama.generate(think=False) 原始返回 --
  done_reason  : stop
  eval_count   : 7
  response 长度: 7
  thinking 长度: 0
  response repr: '[p.955]'
```

**`eval_count = 7`，`done_reason = stop`，`thinking = 0`。**

不是截断，不是被剥离，是模型**只生成了 7 个 token 就认为答完了**。

### 环境变更

| | v3full 时期（会话四记录） | 故障时 |
|---|---|---|
| ollama 服务端 | **0.31.1** | **0.32.3** |
| ollama-py | — | 0.6.2 |
| qwen3:8b | 4 周前拉取，未变动 | 同 |

0.32 有一个结构性变化：`think=True` 时推理内容放在**独立的 `thinking` 字段**返回，而 0.31 时代是内嵌在 `response` 里的 `<think>...</think>`（这正是 `_strip_think` 存在的理由）。接口语义变了，`think=False` 下模型对**完形填空句 / 关键词碎片**这类非疑问句形式的输入，不再自发写正文，只回一个引用标签。

代码、向量库、模型权重、检索行为、打包逻辑**全部未变**。变的只有 ollama 服务端版本。

## 四、修复

在 `think=False` 保持不变的前提下（`think=True` 会撑爆 `num_predict=300` 导致空返回 → 假拒答，即踩坑#11 原样复现），只补一句提示词说明。

四个变体在 2 道失败题 + 2 道对照题上探针测试：

| 变体 | 失败题救回 | 对照题保持 | 对照题正文长度 |
|---|---|---|---|
| V0 原版 | 0/2 | 2/2 | 608 |
| V1 「不许只给标签」 | 2/2 | 2/2 | **253（−58%）** |
| V2 「标签本身不算答案」 | 2/2 | 2/2 | 480 |
| **V3 「题面可能是填空句或关键词碎片」** | **2/2** | **2/2** | **511** |

选 V3：修复效果与 V1 相同（对失败题输出逐字节一致），但对正常题扰动最小。

> V1 的输出与 v3full 存档答案**逐字节相同**：
> `Acanthamoeba keratitis can lead to blindness if left untreated. [p.955]`
> 证明 ollama 0.31 时代模型本来就是这么答的，补一句显式指令即可恢复。

**250 题回归**：可答 110/119 = 92.4%、模糊 27/56 = 48.2%，与 v3full 计数逐项相同。
**全量 4432 题**：见《v7 交付口径》。

## 五、副产物发现

### `think=True` 不设 seed 不可复现

| 模式 | 3 次重复 |
|---|---|
| `think=False` np=300 | **1/3 —— 稳定** |
| `think=True` np=900 无 seed | **2/3 —— 发散** |
| `think=True` np=900 seed=0 | 1/3 —— 稳定 |

`temperature=0.0` 并不保证 ollama 端确定性。`think=False` 恰好稳定，这解释了 v6chk 与 v6b 为何逐题一致。

**影响**：排查过程中曾有一次 `think=True` 打出完整正确答案，据此推断"模型有能力答只是被抑制"——那是三次里的一次，是运气。任何 `think=True` 的单次实测都不能当证据。若未来启用 `think=True` 路径，**必须设 seed**。

### `_generate` 的静默降级

`except Exception:` 无任何日志。若降级真的发生，整轮评测的数字其实来自另一种调用模式，而产物里看不出任何痕迹。已加计数与首次告警。

### `_vl_to_prose` 从未被真正验证

本次事件从 `_vl_to_prose` 的回归验证开始，结论是**那次不达标与它无关**。但全量跑的是 `--no-vl`，**它至今没有在 VL 开启的条件下被验证过**。这条待办不能随根因澄清一起消失。

## 六、沉淀的机制

针对"故障能被静默地跑过去"这一类问题，加了四层自证：

| 机制 | 位置 | 解决什么 |
|---|---|---|
| `chunking_fingerprint()` | `main.py` | 哈希 HEADING_RE + CHUNK_TARGET/MAX + EMBED_MODEL + `semantic_chunks`/`_vl_to_prose` 源码。分块逻辑改一个字就变 |
| `build_manifest.json` + chroma 集合元数据 | 向量库目录 | 库自己记住是哪版代码、什么时候、多少块建的 |
| `env_fingerprint()` | `main.py` | ollama 服务端版本、ollama-py 版本、模型量化与参数量 |
| `_fingerprint.json` | 每个评测结果目录 | 每轮评测自证：分块指纹、PROMPT 变体与哈希、闸门值、降级次数、陈旧库题数 |

配套：`get_collection()` 进库前自动比对指纹，不一致大声告警（`DISTILL_STRICT_LIB=1` 可设为致命）；`run_eval_batch.py` 在建库后和 `--skip-build` 时都校验，不一致默认跳过该书。

## 七、教训

**1. 环境是变量，不是背景。**
代码指纹齐了、数据产物指纹齐了，根因还是从指纹的缝里漏了过去——因为它根本不在仓库里。凡是能影响输出的东西都必须进指纹，包括那些"以为不会变"的外部服务。

**2. 中间指标不能替代终局指标。**
「块数 1441」只证明分块逻辑同源，不证明结果可复现。当时据此宣布"结论确定"，多花了一轮。判据始终只有重跑出来的数字。这与前序 `compare3.py` 只看 token 不看质量就判"收益不足"是同一个错误形状。

**3. 只覆盖一半的校验，比没有校验更危险。**
`.built_book` 校验了书-库绑定，让所有人误以为库的一致性已经被管住了。它提供了虚假的安全感。

**4. 单次实测不能当证据。**
`think=True` 三次里有两种结果。在确认可复现性之前，任何一次运行都只是样本。

**5. 假设的价值不在于对，而在于能被便宜地证伪。**
四个假设错了三个半，但每个都是几分钟就能验的，所以整体只花了一个下午。如果当时直接照着"分块退化"去改代码，那才是真的翻车。

**6. 「字面不出现」不等于「信息不存在」。**
论证"某信息不在语料里"必须做语义级验证，字符串匹配不够。
本项目**在同一个错误上栽了三次**：

- 第一次：不可答探针的构造判据 `verified 0 occurrences`。46 道判为编造的题里，
  5 道是术语字面不出现但概念在书中，模型基于真实内容作答反被判为幻觉。
- 第二次（会话六翻车 #5）：图内题 GT 不合格，12 道里 8 道的"图内独有"其实正文有，
  **只差一个 `the`**。当时已写下教训「多来源场景下字面反查不充分，需同义变体反查」。
- 第三次：图题生成器的 L4 去重。299 个判为"图内独有"的标签中，**241 个（81%）是假的**
  ——正文写「The frontal plane … often referred to as a coronal plane」，
  图内标签写 `Frontal (coronal) plane`，字面不匹配即被判为独有。
  更糟的是它有**方向性**：系统性地滤掉真正的解剖学名词，留下 VL 加了括号注解的那些，
  于是题集测的成了"VL 写法特殊的字符串"，而非"图内独有的信息"。

第三次是在前两次都已发现、且教训都已写进文档之后犯的——**记录一个坑不等于避开它**。
写进"教训"章节只能在事后复盘时被读到，避不开下一次；必须把它变成**代码里的检查项**：
凡涉及"某信息不在 X 中"的判断，一律要求语义级验证。
修法见 `make_figure_eval.py` 的 `in_text_layer()`：字面 → 去空格 → 去括号核心短语
→ 内容词同窗共现，四道比对任一命中即认为正文已有。

**7. 判据的样本量要匹配判据本身。**
PROMPT 变体探针只用了 4 道题，判据「失败 2/2 + 对照 2/2」是必要不充分的——它测不出 V1 把正常答案压短 58% 这种系统性风险（那是靠正文长度这个副指标看出来的）。同理，250 题回归集里只有 75 道不可答，**测不出幻觉率的变化**。回归集的构成决定了它能测什么，不能默认它对所有指标都有效。
