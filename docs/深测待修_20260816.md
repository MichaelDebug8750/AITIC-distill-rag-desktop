## 1. 首次使用错误地默认开启教材外补充（高优先级）

- `webui_index.html` 的 `#extendAnswer` 带有 `checked`。
- 初始化代码只在 localStorage 已存在时改写 checked；新浏览器没有该键，因而沿用 HTML
  的开启状态。
- 同一处注释明确写着“首次使用默认关闭，优先保证严格溯源”，行为与设计相反。
- 2026-08-16 用全新无头 Edge profile 实测，首页立即显示“教材外补充”激活标记；这不是
  历史 localStorage 污染。
- 页面同时承诺“每句话可溯源到原文页码”，默认展示未经溯源的模型常识段会让产品口径
  自相矛盾。

已修：移除 HTML `checked`；初始化无论键是否存在都显式设置
`extendAnswer.checked = saved === '1'`；增加静态测试和全新浏览器请求载荷测试，证明首次
提问发送 `extend:false`，用户明确开启后才发送 `true`。

全新 Edge 上下文的真实 fetch 载荷已验证：首次 `initialChecked=false`、请求
`extend=false`；显式开启后第二次请求 `extend=true`，localStorage 持久化为 `1`。

## 2. 三个表单控件缺少明确可访问名称（低风险）

桌面与 390px 移动端自动审计均发现：

- `#scopeFrom`：需要 `aria-label="页范围起始页"`；
- `#scopeTo`：需要 `aria-label="页范围结束页"`；
- `#pdfFile`：需要 `aria-label="选择要建立知识库的 PDF 文件"`。

两个页码框位于同一个隐式 label 内，无法给辅助技术提供互不相同的名称。已补齐上述名称；随后重跑
HTML parser 审计、键盘焦点审计与桌面/移动端截图。

修后真浏览器结果：桌面/移动端 80 个控件均有可访问名称，控制台错误和失败请求为 0；
Ctrl+K、抽屉与移动侧栏的 Tab 锁定、Escape 关闭及焦点返回均通过。

## 3. 回答模式文案与实际校验链路不一致（中优先级）

- UI 写“快速回答（跳过校验）”，但后端只是跳过第二轮补充检索/生成；共享
  `_finalize_agent_answer` 仍会执行引用校验和逐句语义核验。因此“跳过校验”会错误暗示
  快速回答未经安全校验。
- `auto` 与 `deep` 在当前“全做 Agent”决议后已走同一分支：答得出时第一轮后都必进
  第二轮，第二轮后的继续条件也相同。下拉框同时保留“Agent 校验”和“深度分析”是两个
  行为相同的选择，徒增理解成本。

已修：把 fast 改为“快速回答（单轮生成）”，说明仍执行最终引用/逐句核验；界面去掉重复
的 deep 选项（后端保留兼容值），诊断动作改选 auto；现场 A/B 的模式臂改名“单轮生成
vs Agent 校验”。增加静态守卫，防止以后再次把“少一轮生成”写成“无校验”。

## 6. 切库与单库检索存在串库竞态（高优先级，已确定性复现）

`_activate_library` 改写全局 `M.DB_PATH` 时持 `_pipeline_lock`，但
`_retrieve_selected` 的单库快速路径没有持同一把锁。它先判断目标 A 的路径等于当前
`M.DB_PATH`，随后 `_retrieve → _collection` 才再次读取全局路径；两步之间若切到 B，
就会读取 B 的块，却按先前的 target 把元数据标成 A。引用页码和书名都会看起来合法，
因此比显式报错危险。

`.repro_switch_race.py` 不访问数据库或模型，通过事件精确控制交错，当前构建稳定得到：

```
DOC=read-from:...SIMULATED_LIBRARY_B
TAGGED_LIBRARY=A
CROSS_LIBRARY_MISMATCH=True
```

修复包含两层：

1. 单库检索不再在无锁状态下“比较全局路径后再读全局集合”；要么在同一
   `_pipeline_lock` 临界区完成，要么始终按 target 的绝对路径打开集合。
2. 每个问答请求在入口把缺省的“当前库”解析成确定 ID，第二、第三轮复用该 ID；否则
   用户在两轮之间切库时，即使每次单独检索都正确，也可能把 A/B 两本的证据合并。

修后保留原复现为回归测试，并补流式/非流式多轮冻结库 ID 的守卫。

修复后确定性复现输出为 `CROSS_LIBRARY_MISMATCH=False`；完整单测 407 项通过。

## 7. 保留首轮答案时证据索引漂移（高优先级，已修复）

多轮检索会锁住前三个块、替换第 4 至第 8 个块。若首轮答案合格而后续轮生成失败，
`_adopt_next_round` 会保留首轮答案和其引用索引；旧实现却继续把合并后的 `docs/metas`
交给最终核验与来源列表。于是首轮的 `[资料 5]` 可能静默改指第二轮的新块，轻则把正确
答案裁成拒答，重则展示看似合法但属于错误证据的页码。

`.repro_retained_round_evidence.py` 用纯数据稳定证明位置漂移：合并前索引 4 指向 `A4/p5`，
合并后同一索引指向 `B1/p102`。正式路径现为每次采纳答案时同时保存该轮
`answer_docs/answer_metas` 快照；最终核验和来源列表只读取该快照。流式、非流式两条路径
均有回归守卫，并与冻结知识库 ID 的守卫共同通过 407 项单测。

## 8. 对照与批测的缺省当前库未冻结（中优先级，待英文实验后修）

`/api/compare` 和 `/api/batch` 都允许调用方不传 `libraries`，此时 `api_ask` 会使用当前
激活库。两个端点会连续调用多次 `api_ask`；若用户在执行期间切库，两个对照臂或同一批
题可能落到不同教材，结果却仍显示为同条件对照。显式传库时不受影响，当前英文 A/B
运行器也逐题显式传入知识库 ID，因此不污染正在进行的实验。

修法：端点入口用 `_resolve_library_targets` 把缺省当前库解析为确定 ID 列表，之后每一臂/
每一题只传冻结列表；添加在两次内部调用之间切换 active ID 的确定性回归测试。

## 10. 逐句裁剪后可只剩带页码的拒答残片（中优先级，待实验后修）

`hypercapnia` 的核心定义被逐句核验裁掉后，最终只剩：

```
[p.1220] The material does not provide further details on the definition of hypercapnia.
```

自动评分因仍含题目关键词而记为命中，实际没有回答定义。根因有两层：拒答检测只在逐句裁剪
前运行；开头孤立的合法引用又挡住了锚定在答案开头的窄拒答正则。

对当前结果与上一轮完整英文结果合计 5963 条离线模拟“逐句裁剪后重跑现有窄检测，并在
检测时忽略开头连续合法引用”，共收口 23 条：当前评分中的库外编造 11、模糊题非命中 10、
自动假命中 2。逐条审阅没有一条真正回答了原问题的命中；其中若干会给出相关概念，但开头
已明确承认原查询在材料中无据。只看“忽略开头合法引用”这个增量仍仅命中 `hypercapnia`
1 条。待 manifest 验收后补行为测试；不能借机复活已被 1007 题实验否决的通用放宽正则，
也不能复活“后面还有相关内容就放行”的铺垫补丁。

## 11. 相邻重复引用是系统性排版缺陷（低风险，待实验后修）

当前 1561 条阶段性结果中有 11 条（约 0.7%）出现 `[p.448] [p.448]` 一类相邻同标签，跨
多本书、问题类型和 A/B 两臂。按项目标签规范化再统计仍是同一批 11 条，没有隐藏的
`[p1] / [p.1]` 变体。逐句核验的已支持重组会先删旧标签再追加一个规范标签，因此重复来自
模型原句，不是核验器制造。

修法：在布局归一和 claims 映射前，只删除相邻、其间无正文、规范化后相同的合法标签；
不同页、多库 `K1:p.1 / K2:p.1` 和普通方括号必须保留。

## 12. source 卡把检索候选误称为“引用来源”（产品口径，待实验后修）

后端 `_sources_from` 的契约是返回实际打包进模型上下文的全部候选块，不是只返回最终答案
引用的页；保留这些候选对无标签但由材料支撑的证据链仍有价值。前端却写“引用来源”。阶段性
1892 条中，1236 个已作答响应共有 4813 张 source 卡、正文仅引用约 2029 个不同页；1082 个
答案（87.5%）含未引用卡，中位每答 4 张卡而正文引用 1 页。

不删后端证据，前端标题改为“本轮检索证据（含未被正文引用的候选）”，避免把上下文候选
冒充答案引用；正文方括号与证据链仍是实际引用/支持关系的权威口径。

## 13. 流式升配原因缺少显式转义（纵深防御，待实验后修）

前端 `escalate` 事件把 `d.reason` 直接送入通用 `el(..., html)`。当前后端只会发送两条固定
常量，用户不能控制，因此不是现有可利用漏洞；但未来若 reason 携带动态文本会形成脆弱注入点。
改为创建节点后写入 `textContent`，并增加静态守卫。其余模型答案、历史、书名、来源、证据链、批量/
对照结果及属性值已逐调用点确认分别使用 `escapeHtml` / `escapeAttr`。

## 14. 被采纳答案冻结了 docs/metas，却没有冻结对应 dists（高优先级，待实验后修）

第 7 节修复后，首轮答案被保留时会同时保留生成该答案所用的 `answer_docs/answer_metas`，
避免后续检索重排后把引用索引指向别的块。但 0.99 证据下限和 `_agent_payload` 仍读取循环末尾
的全局 `dists`：若第二/第三轮补充检索已经发生、其新答案却被 `_adopt_next_round` 拒绝采用，
最终就会用“旧答案从未看过的检索距离”决定是否放行，并据此计算可信度/停止原因。

确定性反例：首轮答案对应最优距离 1.10（本应被 0.99 下限拦截）；补检索带来 0.80，但新答案
因引用失败未被采用。现代码保留首轮答案和首轮来源，却用合并后的 0.80 取消证据下限。反向
误杀较少见，因为合并会保留首轮前三块；主要风险是静默放行。

修法：与 `answer_docs/answer_metas` 同时维护 `answer_dists`，每次真正采纳新一轮答案时三者
一起切换；最终证据下限和 `_agent_payload` 只读取 `answer_dists`。流式、非流式各加行为/
源码守卫。正在运行的 focus 候选已经因双遍人工安全反例被否决，因此无需重开该候选实验；
最终默认构建的英文/中文全量必须在此修复后重新运行，当前 A/B 的 A 臂不能冒充最终基线。
