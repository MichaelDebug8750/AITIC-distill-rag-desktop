## 一、会议决议执行：全做 Agent

会议纪要原话「简单和复杂分开／简单走 RAG／复杂走 AGENT／但是等待时间太长，不如全做 AGENT」，
本轮按「全做 AGENT」执行。

**改法**：`_should_agent_continue` 在 `auto` 档第一轮无条件继续，不再按 `_detect_intent`
的路由结果分流。意图识别保留并继续展示，但不再是路由开关。

**一处按判断收窄**：拒答不进校验轮。检索闸门已判定证据离题太远，补一轮只是把同一个
结论重算一遍——实测库外题走这条路 0.5–0.9 秒返回，硬塞一轮变成 20 秒，正是纪要要避免的
「等待时间太长」。若 `should_escalate` 认为补检索可能翻案，仍然继续。
**这一条是我替用户做的判断，需要确认；若要字面意义上"所有题一律两轮"，改一行即可。**

**实测代价**（同一批 6 题，改前/改后各一次，机器满速时）：

| | 改前 | 改后 |
|---|---|---|
| 简单题平均 | 10.4s（1 轮） | 13.6s（2 轮），+31% |
| 复杂题 | 10.4–20.5s | 17.8–20.6s |
| 库外题 | 0.5–0.9s | 0.5s（未变） |

比预估的翻倍要好：第二轮复用已检索证据、只做补充检索，不是从头再来。

### 连带堵上的隐患：校验轮不得成为降级通道

改造前第二轮**只在第一轮失败时**触发，所以「非空就替换」是安全的。改成每题必走校验轮后，
若仍无条件替换，一个引用全命中的好答案会被第二轮顶掉。新增 `_round_is_clean` /
`_adopt_next_round`：

- 上一轮不干净 → 照旧采用新一轮（本来就是为补救才跑的，包括新一轮给出诚实拒答的情形）
- 上一轮已经干净 → 新一轮必须同样干净才替换

"干净" = 非拒答 + 引用全命中 + 正面回答了问题（只吐引用标签不算）。
非流式与流式共用同一套规则，测试锁住 4 个调用点，防止两条路长出两个准确率口径。

## 二、修掉的真 BUG

### 1. 逐句裁剪后留下悬空指代（用户截图暴露）

问「什么是梦」，7 条结论裁掉 5 条，剩下的第一句是「**它**让我们从现实中解放出来……」——
定义「梦」的那句被裁走了，「它」再无先行词，界面把一句主语悬空的残句当作答案呈现。

根因：按下标删句后直接空格拼接，**没有任何一步检查剩余文本还能不能独立成文**。

修法：`kept` 改存 `(原下标, 文本)`；新增 `_drop_orphaned_claims()`，当某句前面确实断了
下标、且句首是回指词时，把这句也去掉，反复扫到稳定为止。
**绝不替它补主语**——我们不知道「它」指什么，编一个正是这套系统要防的事。

只认真正的回指词（它/这/该/其、it/this/they…），不认「然而/因此」这类连接词：连接词接在
别的句子后面读得通，只有当它升为整段首句时才去掉这个语篇标记。

### 2. 状态文案前端写死，与核验结果矛盾

`renderAgentSummary` 里 `path !== 'agent_loop'` 就显示「快速 RAG · 首轮证据充分」，
完全不看核验结果。截图里 7 条删掉 5 条、0 条原文匹配、可信度「低」，状态却写着「证据充分」。
后端 `stop_reason` 早已算出，前端没用。已改为使用后端结果，并让后端把裁剪/悬空/未判定
都算进措辞。

### 3. `e.currentTarget` 在定时器里必为 null

`webui_index.html` 复制/导出对话的空对话分支：

```js
if(!text){ e.currentTarget.textContent='暂无对话';
           setTimeout(()=>e.currentTarget.textContent='⧉ 复制对话',1300); return; }
```

`currentTarget` 只在事件派发期间有效，回调返回后浏览器置为 null，1300ms 后必抛
`TypeError`，按钮文案**永久卡在「暂无对话」**。已改为在派发期内取住节点引用。

### 4. 裁剪后重拼把段落压平（静态复查发现）

`" ".join(...)` 重拼——只要有一句被裁或被规范化，多段答案就压成一整坨，本轮做的排版
工作基本被这一行抵消。新增 `_claim_separators` / `_rejoin_kept`：对着**原文**记下每条结论
前面的空白，重拼时照抄。

### 5. 首句连接词被无故剥离（静态复查发现）

`_strip_leading_connective` 原本无条件作用于首句，连"一条都没裁"的答案也剥，还顺带把
`changed` 置真，逼着没问题的答案走重拼路径。已限定为「原首句被裁、后句被顶上来」才剥。

## 三、对话感：形态放松到"类似即可"

老师要 ChatGPT 那种"一句话先答 → 分面展开"的手感。这不只是提示词的事——前端原本
`ansEl.textContent = d.answer`，**根本不渲染 markdown**，模型吐的 `**` 会变成字面星号。
所以是四处配套：

1. **提示词**：一句话先答；分面小标题与要点列表**都是可选项**，由模型按内容决定；
   分段则写死（只写"prefer short paragraphs"时模型一行到底）。
2. **前端渲染** `renderAnswerBody()`：**先转义、再按白名单还原**，白名单只有段落、
   `- ` 要点、`**粗体**`。链接、图片、原始 HTML 一律不认。
3. **逐句切分**改为先按行再按句，否则一张要点列表会被粘成一条巨型"结论"。
4. **排版归一** `_normalize_answer_layout()`：纯空白处理，一个字不改。

三个只有实测才暴露的问题：简洁档靠"偏好劝退"无效（照样吐 3 个小标题，改成结构规则
整段不发才归零）；模型不肯吐空行；核验重建又把段落拼平（见上第 4 条）。

**拒答未退**：形态规则始终排在拒答契约之下，且受证据闸门 `_STYLE_GATE_MAX = 0.96` 管辖。
6/6 精确输出 `[NO REFERENCE FOUND]`（3 题 × 标准/详细两档）。

纪要「pipeline 自闭环系统，要循环起来」原先只闭了一半：反馈能落盘、能导出回归集，

**返回的不是准确率。** 这些样本的标准答案从未人工订正——keywords 是从"那条被判为错"的

答案是否变了。系统只回答"改没改"，"改没改对"仍需人工判断。返回体里写明了这条边界。

## 十一、全量暴露的核心问题：可信度恒为「低」（需要你决策）

### 现象

演示三题（答辩现场要问的那三道）跑下来，可信度**全是「低」**。

### 根因不在可信度计算，在上游

| 演示题 | 结论句 | 带引用 | 无引用 | 未判定 | 可信度 |
|---|---|---|---|---|---|
| Think Python | 5 | 1 | **4（80%）** | 4 | 低 |
| Dreams | 6 | 2 | **4（67%）** | 5 | 低 |
| Criminal Law | 4 | 3 | 1（25%） | 2 | 低 |

`_claim_needs_support_check` 第一条就是「没有引用 → 送逐句核验」。无引用句送进去
绝大多数判不出来 → 记「未判定」→ 可信度被拖到「低」。数字一一对应。

**这是本轮对话式改动的副作用**：放宽文风后模型开始自由铺陈，写出大段自己引不了的
解释句。而界面副标题写的是「每句话可溯源到原文页码」——行为与产品承诺矛盾。

### 试过的办法：无效

把逐句挂引用从建议升级为硬要求（「引不了就别写」，唯一豁免是"材料未覆盖"的收尾句），
重跑同三题：

```
无引用句占比：改前 9/15 = 60%  →  改后 10/17 = 59%
三题可信度：  低/低/低         →  低/低/低
```

**基本没有效果。** 且 n=3 分辨不出 1 个百分点（本项目噪声底是同配置重跑 0.6–1.5% 翻转），
所以严格说是「三题看不出效果，要全量样本才能判」。提示词规则予以保留（方向正确、
写明了契约、对更大模型可能有效），但**不能声称它解决了问题**。

### 这是一个真实的产品张力，三选一

qwen3:8b 做不到「既像人讲话、又每句可溯源」。三条路：

**A. 代码强制**：核验后丢弃所有无引用句。真正做到逐句可溯源，可信度会明显上升；
代价是答案砍掉约 60%，回到当初挨批的"检索结果"感。

**B. 维持现状**：对话感好，但可信度几乎恒为「低」。注意——**这个「低」是诚实的**，
系统确实没法为 60% 的句子提供出处，它没有说谎。

**C. 分层呈现**：把有引用的结论和无引用的解释在界面上分开，后者标「扩展说明 · 无独立出处」，
不计入可信度。这条最接近老师最初提的"分两部分"，两个要求都能满足，但属于产品语义改动，
我不擅自做。

我倾向 **C**，但这需要你拍板。全量跑完后会有 121 道可答题的真实无引用句占比，
比三题的样本可靠得多，到时再定更稳妥。

## 十二、全量中间结果（124/196 快照）与续跑方式

### 结果

```
精确拒答      73/73 = 100.0%      编造 0.0%
可答命中      45/51 = 88.2%       未命中 1，过度拒答 5
无引用句      116/205 = 56.6%

```

**零编造 + 100% 精确拒答**：全做 Agent 之后核心承诺未退化。

### 一个必须修正的说法

此前写的「可信度恒为低」不准确。实测分布是 低 32 / 中 13 / 高 1，且与无引用句强相关：

| 可信度 | 题数 | 无引用句均值 | 未判定均值 | 裁剪均值 |
|---|---|---|---|---|
| 高 | 1 | 17% | 0.0 | 0.0 |
| 中 | 13 | 31% | 0.0 | 2.2 |
| 低 | 32 | **65%** | **3.7** | 1.4 |

低可信度组的无引用句是中/高组的两倍多。**可信度信号本身是准的**——它忠实反映了
「这个答案有多少句给不出出处」，不是缺陷。问题在于模型有 57% 的句子引不了。

这让第三条路（分层呈现）更站得住：中/高组无引用句仅 30%，说明**模型能引就会引**；
把低可信度那批里的解释性铺陈单独标为「扩展说明 · 无独立出处」、不计入可信度，
可信度分布立刻有意义，而对话感不丢。仍待用户拍板。

## 十三、两段式答案（会议决议落地）

老师原话：「分两部分，一类是只从书中来，第二 part 是参杂模型常用知识库进行补全」。
用户定的排法是**上面放模型常识补全的完整解答，下面放只用教材的溯源版本**——
可读的在前，可审计的在后。

```
┌ 完整解答            [含模型常识 · 未经溯源]
│ 梦是完全脱离清醒生活中体验到的现实……（零引用标签，可独立读完）
└──────────────────────────────────────
── 教材依据 ──────  [逐条可溯源 · 参与可信度计算]
  梦是完全脱离……[p.46]   从功能上看，梦是对睡眠中……[p.47]
  引用来源 / 引用校验 / 证据链 / 可信度
```

### 三处关键改动

1. **上段提示词从「补语」改成「完整解答」**。原文是「别重复教材已说的、只补它没说的」，
   那种文字拎到最上面就是半截话。现在以教材内容为骨架，只在教材留白处补，
   并硬性约束 **Never contradict the textbook part**——两段同屏摆着，互相矛盾比不写更糟。
2. **上段在服务端最后生成**（必须等所有溯源判定算完，确保它无法影响任何指标），
   但要显示在最前面，所以前端先占位后填充。
3. **默认打开**。两段式是默认形态，不是可选项。

### 必须守住的那条线

**库外题实测：下段仍然精确输出 `[NO REFERENCE FOUND]`、`abstained=True`。**
如果上段的存在动了 `abstained`，全量那 100% 拒答准确率就作废了。没动。

耗时：库内题 14 秒（两次模型调用），比单段多约 3 秒。

## 十六、扩容全量结果与据此做的两处修改

### 结果（986 题 / 12 本教材 / 5 个学科）

```
不可答题精确拒答   89.2%      编造 10.8%（30 条）
可答题命中         72.9%      过度拒答 / 未命中见报告
无引用句           58.9%
可信度             低 461 / 中 127 / 高 13
```

对比只有 3 本书时的 194 题：拒答 100% → 89.2%，编造 0 → 30 条。
**窄样本把一个真实弱点完全盖住了**，这正是扩容的价值。

### 本轮核心发现：语料规模同时抬高召回与幻觉

| 分组 | 题数 | 可答命中 | 编造率 |
|---|---|---|---|
| 大库 ≥4000 块 | 568 | 73.8% | **17.7%** |
| 中库 1k–4k | 243 | 71.9% | 3.9% |
| 小库 <1000 | 47 | 64.0% | **0.0%** |

三档单调，不是二分组的巧合。机制：块越多 → 检索总能找到语义相近的内容 →
该答的题证据更足，不该答的题也「看起来有据」。

检索距离分布证实了这一点（不可答题的最优距离中位数）：

```
小库 1.142   中库 1.105   大库 1.034      旧闸门 1.1762
落在闸门内（被当成有依据）：64% → 70% → 88%
```

**旧闸门对任何规模都太松，形同虚设**——不只是大库的问题。

### 修改一：放宽散文式拒答的识别

30 条编造里有 8 条是模型**自己承认了没有**，只是措辞是
`not directly mentioned` / `not directly defined` / `not directly addressed`，
而原正则只认 `not explicitly`。漏判的后果不是少一条拒答，而是把模型
顺带写的邻近内容当成了有据答案。

放宽副词（explicitly/directly/specifically/clearly/expressly）与动词
（增补 defined/discussed）后：8 条全部正确识别，60 条正常答案**零误杀**。
`^` 锚定保留，所以「答了大半、顺带说某点没覆盖」仍不会被误判为整题拒答。

### 修改二：证据下限 `_EVIDENCE_FLOOR = 0.99`

拒答此前完全由模型判断，没有任何代码侧兜底。新增：检索最优距离差于下限时，
无论模型写了什么都改判拒答，并走同一条 `_finalize_agent_answer`，不产生第二套拒答语义。

阈值由扫描定，不是拍的（28 条编造 + 160 条正确答案对照）：

| 阈值 | 拦住编造 | 误杀正确 |
|---|---|---|
| 0.93 | 46% | 7% |
| 0.95 | 43% | 6% |
| **0.99** | **29%** | **1%** |
| 1.11 | 0% | 0% |

取 0.99——0.93 能多拦 17 个百分点，但误杀从 1% 涨到 7%，不划算。

**边界（必须写明）**：样本只有 28 条编造，且阈值在同一批数据上标定，
存在过拟合风险。分规模标定（中库 0.93 拦 100%/误杀 2%、大库 0.87 拦 76%/误杀 15%）
效果更好但样本更薄，暂不做。这是保守的第一版，下一轮全量要复核它是否仍成立。

### 试过但**没有采用**的方案

**词组零覆盖即拒答**。不可答探针的构造是「跨学科真术语 + 回本库验证零出现」，
所以检索块里应当完全不含该术语。实测确实如此——编造组词组零覆盖率 93%、
平均覆盖 5%，命中组 14% / 76%，判别力很强。

但代价是**误杀 14% 的正确答案**，换算到全量约丢 55 条正确回答、命中率掉 7 个点。
拿召回换精度，而两个指标都要看，所以不上。

零覆盖样本很有说服力，值得写进答辩材料：`new federalism`、`voter fatigue`、
`delegate legislator`、`conceptual variables` —— 这些术语在书里一次都不出现，
模型却答得头头是道。这就是幻觉的本质。

### 一个被我否掉的自己的假设

最初按**单词**算术语覆盖，编造组 46% / 命中组 76%，信号不干净，
按那个数据几乎要得出「术语覆盖没用」的结论。原因是
「Explain the term new federalism」被拆成 `new` / `federalism`，而 `new` 到处都是。
改成**词组** 2-gram 后判别力从 46/76 变成 5/76。

教训：指标算不出区分度时，先怀疑自己的特征提取，再怀疑假设本身。

## 十七、修复验证暴露的问题，以及一个方法论错误

### 第一轮验证：预测 1% 误杀，实测 15%

68 道原题重跑（编造组 28 + 命中组 40）：

```
编造修复率        59%（16/27 改判拒答）
正确答案保持率    85%   ← 误杀 15%，而阈值标定预测只有 1%
```

15 倍偏差不是噪声。归因（对 6 条误杀逐条查检索距离）：

| 问题 | 最优距离 | 归因 |
|---|---|---|
| Explain factual cause. | 0.647 | 拒答正则 |
| Explain representability. | 0.643 | 拒答正则 |
| Explain basic elements. | 0.646 | 拒答正则 |
| Summarize what the text covers on defences. | 0.772 | 拒答正则 |
| What does this book say about dreamer? | 0.856 | 拒答正则 |
| What is present work? | 1.086 | 证据下限 |

**5/6 是拒答正则干的，证据下限只占 1 条。**

### 我的验证方法有缺陷

放宽副词后，我用 60 条**存量答案**验证「零误杀」，结论是安全的。那个验证是错的：

> 存量答案由**旧代码**生成，测不出新逻辑对**新生成分布**的影响。

放宽正则后模型新生成的答案常带免责铺垫——
「术语 X 未直接定义，但材料说明了……[p.12]」——开头那句被整体判成拒答，
后面真正的答案连同引用一起丢掉。旧数据里没有这种句式，所以测不出来。

**教训：改动会影响模型输出分布时，必须用新生成的数据验证，不能用存量数据。**

### 修法：一个机制管一件事

想加「铺垫后仍有带引用实质内容就不算拒答」的判据时，撞上一个本质问题：

```
"The term X is not directly mentioned. However, …[p.12]"
```

这个形态**同时**出现在两种情形：
- 不可答题 —— 后面是离题的邻近内容，该拒答
- 可答题 —— 后面是带引用的真答案，该保留

两者文本形态完全相同，**纯文本规则分不开**。所以改成分工：

- **拒答正则**只管纯拒答（尾部没有带引用的实质内容）
- **证据下限**按检索距离判这种「铺垫 + 实质内容」的情形——
  距离远的（不可答）拦掉，距离近的（可答）保留

别让正则去猜它猜不出来的东西。这一条写进了测试注释，防止后人再把两件事混在一起。

## 十八、噪声底 9%，以及它推翻了什么

### 测量

同一份代码、同一批题（23 道原本命中的题）、连跑 3 次：

```
结果不稳定 2 条 = 9%
逐句裁剪条数：均值 2.2，最大 7，为 0 的占 14%
```

翻转样本：

```
What does this book say about dreamer?        拒答序列 = [True, False, False]
Summarize what the text covers on defences.   拒答序列 = [True, True, False]
```

根因：`_semantic_support_guard` 会调模型逐句判断，裁剪到剩空时走 `refused` 分支。
这一步**本身带随机性**，而它决定了一道题最终是作答还是拒答。

### 它推翻了什么

我做了三轮 68 题 A/B 对照，差异是 3pp，而噪声底是 9%：

| 轮次 | 改动 | 修复率 | 保持率 |
|---|---|---|---|
| 1 | 放宽正则 + 证据下限 | 59% | 85% |
| 2 | ＋铺垫补丁 | 41% | 82% |
| 3 | 仅证据下限 | 41% | 85% |

**这些差异全部落在噪声里，三轮对照都不构成证据**——包括我据此回退正则的决定。
我当时把「误杀 6 条」一路归因到自己的改动上，追查单题才发现真凶是逐句核验的随机性，
那条路径今晚根本没动过。

### 哪些结论仍然成立

统计口径要分开看：

| 场景 | 样本量 | 结论是否可信 |
|---|---|---|
| 986 题全量聚合指标 | n≈400 可答题 | **成立**，SE≈1.4pp |
| 规模效应（三档单调） | n=568/243/47 | **成立** |
| 距离分布标定 | 缓存距离，确定性计算 | **成立**，不含生成随机性 |
| 68 题 A/B 对照 | n=28–40 | **不成立**，被 9% 噪声淹没 |

要分辨 5pp 差异，每个方案需跑 200 题以上；三个方案约 600 次调用、2 小时。**未做。**

### 据此的最终定夺（标明依据类型）

| 改动 | 去留 | 依据 |
|---|---|---|
| 证据下限 0.99 | **保留** | 阈值来自确定性的距离扫描（n=188，无生成随机性）；归因显示仅造成 1 条误杀 |
| 放宽拒答正则 | **回退** | 判断，非实测。收益（8 条 A 类）是确定性文本匹配，代价无法在噪声下测出；机制上「铺垫式答案被整体转拒答」的风险真实存在，从保守出发不上 |
| 铺垫补丁 | **回退** | 它是为放宽正则打的补丁，正则回退后失去存在理由 |

**我把「回退正则」明确标为判断而非实测结论**，因为支撑它的那三轮对照已经作废。
若后续要重启这个方案，必须先按上面的样本量要求做实验。

### 方法论教训（两条，都是这轮踩出来的）

1. **改动会影响模型输出分布时，不能用存量数据验证。**
   我用 60 条旧答案验证放宽正则「零误杀」，真机跑出来 15%——旧答案由旧代码生成，
   测不出新逻辑对新生成分布的影响。

2. **做 A/B 之前先测噪声底。**
   webui 路径比 CLI 多了逐句核验这一步，噪声底 9% 远高于 CLI 记录的 0.6–1.5%，
   不能沿用旧数字。没有噪声底，任何小样本对照都是自欺。

## 二十、两臂对照的最终结论：回退

### 结果

同一批 100 道题、各跑 3 次、用环境变量在同一份代码上切换（不改代码做 A/B，
避免"到底跑的是哪一版"的疑问）：

| 臂 | 配置 | 翻转 | 95% 区间 |
|---|---|---|---|
| A | 接地率判据**开启** | 4/100 = **4.0%** | 0.2%–7.8% |
| B | 判据**关闭** | 7/100 = **7.0%** | 2.0%–12.0% |

**Fisher 精确检验 双尾 p = 0.537。**

方向是对的（关掉后更不稳定），但远未显著。两臂只有 3 道题结果不同，
n=100 下完全可能是偶然。**按跑数据之前就写死在脚本里的判据：回退。**

### 为什么不用「方向对」当理由留下它

今晚已经因为「机制听起来对」白试了两个改动。判据写死在 `compare_arms.py` 里、
在看到数据之前就定好，现在照做。这一条比这个改动本身重要。

### 边界（必须写明）

**这不表示判据一定无用**，只表示 n=100 的实验没能测出差异。
要分辨 4% vs 2% 这个量级，每臂约需 800 题（约 8 小时），超出可行范围。

### 用什么检验，以及为什么不看区间重叠

用 Fisher 精确检验而非「95% 区间是否重叠」——后者是常见但不严谨的做法：
区间重叠不等于无显著差异，不重叠也不必然显著。翻转数只有个位数，
Fisher 不依赖大样本近似，更可靠。

统计上还做了两处防自欺：
- 只比两臂**都跑过的共同题**（B 臂是断点续跑的，直接比 100 vs 100 可能比的是不同子集）
- 同题**去重保留最后一条**（续跑时若有题被重复执行，不去重会让计数虚高）

### 实验有效性检查（这一步差点被跳过）

开跑前验证了三层，确认两臂确实跑的是不同代码：

```
命令行     cmd 设 DISTILL_GROUNDING_KEEP=0 后再起 uvicorn，子进程继承
端口隔离   8011 未运行，B 臂 300 次调用全打 8013
代码生效   同一份 webui.py，环境变量 1/0 → _GROUNDING_KEEP True/False
```

**如果环境变量没传进去，两臂跑的是同一份代码，我会得到「两臂几乎一样」，
然后完全合理地得出「判据无效」——而那是假的。** 这类失效模式不报错，
只给出一个看起来正常的数字。

### 噪声底的最终值，以及一个自我更正

**约 4%**（100 题 × 3 次）。此前基于 23 题报的 9%/17%/13% 是小样本高估——
n=23 时一条翻转就顶 4.3 个百分点，那三个数其实是同一个值在抖。

我曾以「噪声 9%，对照无效」为由回退放宽正则。**回退这个动作结果上没错**
（4% 噪声下，68 题对照要分辨 3pp 差异仍需 n≈200），**但当时给出的理由是虚高的数字**。

### 附带发现：大库更稳定

A 臂大库 1.8% vs 小中库 5.6%；B 臂 5.3% vs 8.3%。两臂同向。
合理——大库检索到的证据更充分，判定不在边界上摇摆。这和「大库编造率更高」
（17.7% vs 3.9%）是同一机制的两面：证据越充分，该答的答得越稳，
不该答的也越容易被误认为有依据。

### 今晚三次尝试的总账

| 尝试 | 结果 | 依据 |
|---|---|---|
| 放宽拒答正则 | 回退 | 收益确定（8 条），代价无法在噪声下测出，保守起见不上 |
| 裁光前二次确认 | 回退 | 复测 9% → 17%，更差；是 amplifier 不是 damper |
| 并入确定性接地率 | 回退 | 正式两臂对照 p=0.537，未能证明有改善 |
| **证据下限 0.99** | **保留** | 阈值来自确定性距离扫描（n=188，不含生成随机性） |

**下游叠加判据动不了噪声底。真正的解法在上游——降低生成方差本身
（固定切句、缓存核验结果），未做。**

## 二十二、稀释假设：成立，但改法被数据否掉

### 假设

证据下限 `_EVIDENCE_FLOOR = 0.99` 上线后，编造率只从 10.8% 降到 9.3%（1.5pp，
噪声底之内），远低于标定时预测的「拦住 29%」。提出的解释：

标定时我用 `/api/retrieve` 量的是**单次检索**的最优距离；而全做 Agent 之后，
凡是模型答得出来的题都会跑第二轮，`_merge_retrieval` 把两轮结果并起来。
合并只会让最优距离更小或持平（第一轮 top-3 锁位保留）。
**编造恰恰全是「该拒答却答了」的题，全都经过了合并**，所以真实管线里
闸门看到的距离比标定时更小，几乎拦不到东西。

### 实测：假设成立

```
              第一轮距离      合并后距离
编造组 n=26    中位 0.902     中位 0.894     >闸门 5 条 vs 1 条
命中组 n=484   中位 0.721     中位 0.727     >闸门 9 条 vs 5 条
```

编造组用第一轮距离能拦 19%，用合并后只能拦 4%。稀释确实存在。

### 但改法不值得做

```
换用第一轮距离的净效果：
   多拦住编造：4 条
   多误杀正确：4 条
```

**1:1 交换。** 收益 4/28 换算到总指标是 9.3% → 8.0%（1.3pp），
代价 4/484 换算到 707 道可答题约 6 条。两边等量，纯空转。

**决定：不改。**

### 这一步最值得记的不是结论，是过程

第一次测时对照组只取了 80 条命中题，结果是「多拦 4 条编造、**零误杀**」——
按那个数据，这个改动看起来是白捡的收益，我差点就改了。

把对照组扩到全部 484 条命中题后，误杀从 0 变成 4，收益/代价从「4:0」变成「4:4」，
结论完全反转。

**样本不够时，代价侧最容易看起来是零**——因为误杀是小概率事件，小样本大概率一条都抽不到。
收益侧反而容易估准（编造样本本来就少，全测了）。
这种不对称会系统性地让人高估一个改动的价值。

以后凡是「收益明显、代价为零」的测量结果，先问一句：代价侧的样本量够看见它吗？

## 二十三、重复性实测：本构建近乎确定性，「噪声底 4%」站不住

### 实测结果

同一份代码、同一批题、两轮完整全量（第二轮为验证目的重跑）：

```
共同题 972 道
  结果类别翻转     1 / 972 = 0.1%
  作答↔拒答翻转    0 / 972 = 0.0%
  可答题 n=704     翻转 1 = 0.1%
  不可答题 n=268   翻转 0 = 0.0%

编造样本：两轮各 28 条，**同一批 28 条，重合率 100%**
聚合指标：精确拒答 / 编造 / 过度拒答 三项差 +0.0pp，可答命中 +0.1pp
答案文本：968 / 972 = **99.6% 逐字相同**
```

唯一翻转的那道题：`If you want to use a sort that modifies the argument...` 未命中 → 命中。

### 先证明这是真重跑，不是复制

聚合数字一模一样、编造集 100% 重合，第一反应应该是怀疑「根本没真跑」——
`fullrun3.py` 有断点续跑逻辑（读已有输出文件跳过已完成题），复制的可能性是实打实的。
三条证据排除：

```
总耗时       A=137 分   B=138 分        （复制的话应当完全相同）
单题耗时     480 / 972 道不同，最大差 13.8s
答案文本     4 道不同                   （复制的话应当 972/972 相同）
```

另外确认 `webui.py` 里没有任何答案缓存（只有 PDF 路径缓存与建库期 VL 缓存），
`/api/ask` 不会返回存量结果。

### 与此前「噪声底 4%」的冲突

`noise_big.py` 测的是**同一个指标**（`abstained` 是否翻转），100 题 × 3 次，
两臂分别是 4.0% 与 7.0%。而全量两轮的同一指标是 **0.0%（0/972）**。

**我没有验证过的解释。** 排除掉的：不是指标口径不同（同一个字段），
不是 `extend` 参数不同（两个脚本都是 `extend: False`），不是答案缓存（不存在）。
剩下最可信的候选是**测量时的并发负载**——批式推理的数值结果对 batch 组成并不不变，
而那两臂是在机器上还有其他任务时跑的，两轮全量则是独占机器顺序跑完。
**这只是假设，没测过，不写成结论。**

**而且有一条反证，得自己说出来**：第二轮全量跑到 618/1007 时，我并发打了
3 道演示题进去（复验答辩用例），也就是那一轮**并非全程独占**。
即便如此，逐题翻转仍是 0/972。若并发真是 4% 的成因，这 3 次并发理应留下痕迹。
样本太小（3 次请求 vs 整轮 1007 题），不足以否掉假设，但足以说明
**这个解释我连自己都没说服**。诚实的表述只能是：**原因不明。**

### 实际影响：凡是以「落在噪声里」否掉的结论都要重看

这一晚我用「差异落在噪声底 4% 之内」这句话否掉过多个对照。在两轮全量所处的
条件下（同机、单序列、无并发），噪声接近零，那句话不成立。

**最要紧的一条是放宽拒答正则。** 翻出 68 题三轮的原始数据：

| 轮次 | 配置 | 修复率 | 保持率 |
|---|---|---|---|
| 轮1 | 仅放宽正则 | **59%** | 85% |
| 轮2 | 放宽正则 ＋ 铺垫补丁 | 41% | 82% |
| 轮3 | 两者都回退 | 41% | 85% |

当初写进代码注释和单测里的结论是「放宽导致两个指标都变差」。
**那是把轮1→轮2 的下降算到了放宽头上——那一跤是铺垫补丁摔的。**
放宽单独看（轮1 vs 轮3）是 **+18pp 修复率、保持率持平**。
回退时我把两个改动捆在一起撤了，等于用 B 的罪证判了 A。

两个依据（「都变差」、「落在噪声里」）现在都不成立，所以**放宽这件事尚未被证伪**。

### 已重开实验

`AITIC_WIDEN_REFUSAL` 环境开关，默认关闭＝线上现行为不动；
开启则副词放宽到 `directly|specifically|clearly`、动词补 `defined|discussed`。
正在跑 n=1007 配对对照，重点看**代价侧**（误杀多少条原本答对的题）——
这正是第二十二节那条教训要求的：小样本最容易把代价看成零。

**判据在跑之前就写死并落进 `compare_widen.py`**：

> 采纳，当且仅当 多拦住的编造 > 0 且 误杀 ≤ 收益的一半。
> 不对称是有意的：编造是不安全失败，过度拒答是安全失败，但也不能无限换。

铺垫补丁不复活——它的失败与样本量、与噪声都无关，是逻辑本身错。

### 教训

**1. 捆绑回退会连累无辜的那一半。** 两个改动一起上、一起撤，
数据只告诉你「这一对不行」，说不出是谁的问题。要么分开上，要么撤之前拆开各测一次。

**2. 噪声底是条件量，不是常数。** 它随并发负载、批大小、硬件状态变化。
拿 A 条件下测的噪声去判 B 条件下的差异，和不测没区别——
更糟的是它给人「我量过了」的错觉。引用噪声底时必须连测量条件一起引。

**3. 写进注释和单测的结论也会错，而且更难纠。** 那条错误归因被我同时写进了
代码注释、函数 docstring 和一个单测的类文档，三处互相印证，看起来像是有据可查的定论。
纠正时要三处一起改。**结论写得越正式，后面越没人回去查它的原始数据。**

## 二十四、校验轮的拒答被当成「降级」丢掉了——实验意外挖出的真缺陷

### 怎么发现的

放宽正则臂跑到一半，我做了一次结构性健康检查（不看收益数字，只看有没有
不该出现的迁移），发现 **3 道题从「拒答正确」变成了「编造」**。

这不该发生。放宽正则在数学上是**单调**的：narrow 能匹配的串 wide 一定也匹配，
所以拒答只会变多、不会变少。反向迁移说明动的不是正则，是别的东西。

逐条打开看，三条的形态完全一致：

```
Q: What are sticky wages and prices?     （经济学题，问的是计算机教材）
  基线   rounds=3  abstain=True   [NO REFERENCE FOUND]
  放宽臂 rounds=2  abstain=False  "Sticky wages and prices refer to..."
```

**轮数变了**：基线跑到第 3 轮拒答，放宽臂第 2 轮就停下且没拒答。

### 根因

```python
def _round_is_clean(answer, cite_check, directness):
    if M.is_abstain(answer):
        return False          # ← 拒答永远"不干净"
    ...

def _adopt_next_round(prev_clean, answer, cite_check, directness):
    if not prev_clean:
        return True
    return _round_is_clean(answer, cite_check, directness)   # ← 拒答被拒绝采纳
```

于是这条路径成立：

```
第一轮：给出带合法页码的答案（引用命中、正面作答）→ prev_clean = True
第二轮：查完证据认定材料里没有 → 拒答
_adopt_next_round：上一轮干净、这一轮"不干净" → 不采纳，保留第一轮
结果：**正确的拒答被扔掉，编造被保留**
```

**「上一轮干净」只说明它引用命中、正面作答，不代表它对。**
不可答题上，第一轮编得有模有样恰恰是最危险的形态——v7 的 49 条幻觉审计里
42 条都带合法引用。这条规则等于**把校验轮对不可答题的纠错能力关掉了**。

**证据强度要说清楚**：这条链路是**推断**出来的，依据是（a）三题的轮数从 3 掉到 2、
（b）基线拒答而放宽臂不拒答、（c）代码里确实存在产生这一结果的唯一路径，
外加（d）一条单测直接证明 `_adopt_next_round(True, [NO REFERENCE FOUND], …)` 返回 False。
**我没有逐轮日志**，所以没有直接观测到"第二轮拒答被丢弃"这一刻。

### 【2026-08-13 更正：这条归因被后续数据否掉了】

拒答采纳臂跑完后做了交叉检查，结论**推翻上面这段归因**：

```
放宽臂反向迁移 3 条，采纳臂反向迁移 3 条，**两臂重合 2 条**
这 4 道题在同代码重跑里全部稳定保持「拒答正确」
```

**采纳臂里 `AITIC_ADOPT_ABSTAIN=1`，也就是"丢弃拒答"这条机制是关掉的**，
可那 2 道题照样从「拒答正确」翻成「编造」。**机制关掉了现象还在 → 它不是成因。**

正确的解读：这几道题**贴着判决边界**，同代码重跑稳定，但只要管线被扰动
（无论是换正则还是换采纳规则，两者都会改变轮数与最终采纳哪一轮，
进而改变发给 Ollama 的请求序列）就会翻面。

于是多出一个必须记住的量：

```
同构建重跑噪声      1 / 972 = 0.1%
跨构建配对噪声      约 3 / 972 = 0.3%   （两臂反向迁移的量级）
```

**跨构建比较的噪声比同构建重跑高一个量级。** 小于这个量级的差异不可归因。
（本轮两个判决 14:46 和 8:39 都远高于它，结论不受影响。）

机制本身（d）仍然成立——单测直接证明了那行代码会丢弃拒答。
**成立的是机制，不成立的是"它造成了这 3 条"。** 这两件事我当时混为一谈了。

而校验轮能纠正不可答题，正是「全做 Agent」这个决定的主要卖点。

### 这个缺陷与放宽正则无关

默认构建里同样存在。放宽只是让后轮更容易产出拒答，于是把它撞了出来。
**它是我今晚自己加的**（`_adopt_next_round` 是「7 处修复」之一，为了防止
校验轮把好答案顶掉）。防的方向对，但把「拒答」和「更差的答案」混为一谈了。

### 没有当场改

把「拒答一律采纳」设为默认，风险方向正好反过来：任何一轮的误拒都能顶掉
好答案，过度拒答会涨。收益和代价都得量。

已挂在 `AITIC_ADOPT_ABSTAIN` 开关后面，**默认关闭＝线上行为不变**，
并补了 3 条单测：记录当前（有缺陷的）行为、开关生效、以及**开关不会顺手
放行普通降级**（否则又变回"校验轮＝降级通道"那个老问题）。

### 教训

**自己加的防护措施要按"新增风险"对待，不能按"修复"对待。**
`_adopt_next_round` 当时是作为 BUG 修复加进去的，跟着 7 处修复一起上线，
没有单独测过。它确实修好了它要修的问题，同时开了一个新洞——
而因为它被归类成"修复"，我没给它做代价侧测量。

**下次凡是"加一条规则来阻止某种情况"，都要问：这条规则会不会把正确的情况也拦掉？**

## 二十五、放宽拒答正则：n=1007 配对重测，**判决不采纳**（这次有据）

### 判据（跑之前写死在 `compare_widen.py` 里）

> 采纳，当且仅当 多拦住的编造 > 0 且 **误杀 ≤ 收益的一半**。
> 不对称是有意的：编造是不安全失败，过度拒答是安全失败；但也不能无限换，1:2 封顶。

### 结果

```
配对 972 题（同题、同机、单序列，两臂唯一差别是那一处正则）

收益  编造 → 拒答正确      14 条
代价  命中 → 过度拒答      46 条        判据上限 7 条
中性  未命中 → 过度拒答    17 条
反向  拒答正确 → 编造       3 条        ← 另有原因，见 §二十四

指标            基线      放宽       差
精确拒答       89.6%    93.7%    +4.1pp
编造          10.4%     6.3%    -4.1pp
可答命中       72.3%    69.6%    -2.7pp
过度拒答       15.2%    18.2%    +3.0pp

合计变动 143 / 972 = 14.7%
```

**3.3:1 亏本。不采纳。** 开关留着、默认关闭，注释和单测都记着原始数据。

> **【2026-08-13 更正，见 §三十二】「3.3:1 亏本」这个说法是错的，撤回。**
> 它只数了 `命中→过度拒答` 46 条，没算反向的 `过度拒答→命中` 28 条回补。
> 净额是 **命中 −19 / 编造 −11，按项目兑换率净值 +3**，落在跨构建噪声
> （约 3 题 / 972）之内。**正确的说法是"证不出有效，也证不出有害"，
> 不是"有害"。** 不采纳的决定不变（没有证据支持改它），但依据从
> "明显亏本"降级为"分不开"。

被误杀的都是货真价实的可答题：

```
Describe computer scientist.      Think Python 里有明确定义
Describe actin.                   A&P 里有整节
Describe disease control.         微生物学里有
Define first rule of labor markets.  经济学里有
```

它们的共同形态是：模型先写一句「材料里没有直接定义 X，但……」当铺垫，
后面接的是**有页码、有内容的正确答案**。放宽后整段被判成拒答扔掉。
这印证了当初那句判断——**这个句式在可答题和不可答题里文本形态完全相同，
纯文本规则分不开**——只是当初我没有数据支撑它，现在有了。

### 最该记住的一点：只看头部指标会拍板通过

精确拒答 **+4.1pp**、编造 **−4.1pp**，两个都是答辩要报的核心数字，
而且都是朝好的方向动的。**如果只看这两行，这个改动会被通过。**
代价藏在另外两行里（可答命中 −2.7pp、过度拒答 +3.0pp），
而且**必须逐题配对才看得出交换比是 14:46**——聚合表看不出这个比例。

### 关于 8/12 那次回退

**决定是对的，理由是错的。** 当初写的两条依据：

1. 「两个指标都变差」——错，那是铺垫补丁的锅（见 §二十三）
2. 「差异落在噪声底 4% 之内」——错，同条件噪声近零（见 §二十三）

现在换成一条有据的：**n=1007 同题配对，14:46，超出预设上限 6.6 倍。**

一个正确的结论配上错误的论证，看起来和有据可查没有区别——直到有人拿它当前提
去推别的东西。这次就是：我拿那两条错依据顺手否掉过别的改动。

## 二十六、拒答采纳臂：**机制是真的，但按它修反而更糟**

### 判据

沿用放宽正则那条，一字未改：

> 采纳，当且仅当 多拦住的编造 > 0 且 **误杀 ≤ 收益的一半**。

同类取舍用同一把尺子，免得事后按结果调判据。

### 结果

```
配对 972 题，唯一差别是 AITIC_ADOPT_ABSTAIN

收益  编造 → 拒答正确       8 条
代价  命中 → 过度拒答      39 条        判据上限 4 条

指标            基线      采纳臂      差
精确拒答       89.6%    91.4%    +1.9pp
编造          10.4%     8.6%    -1.9pp
可答命中       72.3%    70.6%    -1.7pp
过度拒答       15.2%    15.4%    +0.2pp
```

**1:5 亏本，比放宽正则那次还差。不采纳。**

### 为什么亏这么多：校验轮的拒答本身就不可信

这一臂的收益和代价来自同一个动作——**采纳第二轮的拒答**。数据把这个动作的
质量量化了：

```
第二轮拒答被采纳的场合共 47 次
  其中拦对了（本来是编造）     8 次
  其中拦错了（本来答得对）    39 次
校验轮拒答的精确率 = 8 / 47 ≈ 17%
```

**校验轮说"材料里没有"，有 83% 的概率是它自己没找着，而不是真的没有。**

这解释了一件本来看着矛盾的事：`_round_is_clean` 把拒答判为"不干净"、
从而丢弃校验轮的拒答，**逻辑上是错的，效果上却是对的**——
它挡掉的 39 条误杀远多于放过的 8 条编造。歪打正着。

### 对上一节那条归因的更正

见 §二十四末尾新增的更正段：**采纳臂里这条机制是关掉的，那 2 道反向迁移照样发生**，
所以「丢弃拒答造成了那 3 条编造」这个归因不成立。机制存在（有单测），
但它不是那几条的成因。

### 真正该改的不是采纳规则

两次实验（放宽正则、拒答采纳）指向同一件事：

**问题不在"要不要相信拒答"，而在"拒答判得准不准"。**
两次改动都是在下游调怎么用这个信号，而信号本身精确率只有 17%，
下游怎么接都是亏的。要动就得动上游——**为什么校验轮在有据可查的题上
也会说"材料里没有"**。那是检索或提示词的问题，不是采纳规则的问题。

**本轮不做**：这是个新方向，需要先量清楚校验轮拒答的成因分布，
不是今晚能收尾的事。已记在这里，别让它丢了。

### 现状

`AITIC_ADOPT_ABSTAIN` 保留，**默认关闭＝线上行为不变**，3 条单测保留，
`_adopt_next_round` 的注释里记着完整的实验数据（8:39）。
**代码一行没改成默认行为。**

## 二十七、中文能力：第一份量化数据（24 题探针）

### 先说这份数据能承担什么

**它不是准确率，不要那样报。** 24 题、可答题全部出自 `Emacs生存指南`
一本（28 块，属小库）。它只回答一个问题：**中文这条路通不通。**

之所以只有一本：另外两本中文库出不了合格的题。`GNU_make中文手册` 前 30 块
全是目录页（点线 + 页码），`多模态AIGC讲义` 是英文幻灯片碎片配中文翻译。
这与 §二十一记的自动出题失败是同一个原因，不是正则写得不好。

### 出题与校对

人工读原文出题，然后**对着全库完整正文**（28 块 / 10577 字，即全部内容）
逐条机器校对——不是抽样：

```
可答 14 道：证据句逐字出现在原文        14/14 通过
             关键词也都出现在原文        40/40 通过
不可答 10 道：术语在全库出现次数         全部 0 次
```

上一批自动出题的术语↔证据错配率是 39%，那批已作废（§二十一）。

### 结果

```
不可答 10 道   精确拒答 10   编造 0        平均 0.5 秒
可答   14 道   命中 11   未命中 0   过度拒答 3   平均 10.2 秒
```

**三件事值得单独说：**

**1. 拒答契约在中文下逐字成立。** 10 道不可答题的答案**全部逐字等于**
`[NO REFERENCE FOUND]`，没有一道退化成中文散文式婉拒。`is_abstain()` 依赖
这个精确 token，这条契约跨语言没有松动。且平均 0.5 秒——**检索闸门在生成之前
就拦下了**，没有进模型。

**2. 零编造，且零答错。** 14 道可答题里没有一道"答了但答错"。
失败形态只有一种：该答的不答。**在这个系统里这是安全的那一侧。**

**3. 可信度分布明显好于英文。**

```
中文命中题   高 2 / 中 6 / 低 3
英文全量     高 13 / 中 137 / 低 478   （低占 76%）
```

原因大概率是语料形态而非语言：Emacs 那本篇幅短、定义密集，模型答得短、
引用挂得住。**样本太小，不能当成"中文可信度更高"的结论**，但至少说明
76% 恒为「低」不是系统性上限，是语料与答案长度的函数。

### 3 道过度拒答：又是校验轮

```
C-h f 用来查什么？                轮次=2  引用校验=通过
major-mode 的 hook 是做什么用的？   轮次=2  引用校验=通过
一个 Buffer 和 Window 是一一对应的吗？ 轮次=2  引用校验=通过
```

**三道全部死在第二轮**，而且第一轮的引用校验是**通过**的。
这与 §二十六量出来的东西完全一致——校验轮拒答的精确率只有 17%，
它在有据可查的题上照样说"材料里没有"。

中文这边 3/14 = 21% 过度拒答，英文全量是 15.2%，同一个病灶。

### 结论

**中文问答可用，拒答契约可靠，主要缺陷与英文完全同源（校验轮误拒）。**
PRD 里「中英文都要解析」这一条，现在有了第一份可引用的数据——
但只覆盖一本书，**要覆盖 PRD 声称的范围，得人工给另外两本写题，
或者换更适合出题的中文教材**。

## 二十八、「闸门随语料规模标定」——写代码之前就被数据否掉

### 这是我自己写进结论的优化方向

§二十（规模效应）末尾写的是：

> **结论：拒答闸门必须随语料规模标定，固定阈值不可移植。**

规模效应本身是扎实的（两轮独立数据、三档单调）：
大库编造 15.5%、中库 3.7%、小库 0.0%。所以"按库大小分别设阈值"看起来是
顺理成章的下一步。

**动手前先量了一次，结果是：不该做。**

### 量了什么

全量 939 题（1007 题中能映射到知识库的部分）的最优检索距离，
只打 `/api/retrieve` 不调模型，1.8 分钟跑完，且距离是确定性的。

```
分组          类型      n     P10     中位     P90     最大
中库1k-4k     不可答    82   0.956   1.073   1.217   1.252
中库1k-4k     可答     167   0.576   0.748   0.916   1.180
大库>=4000    不可答   142   0.874   1.029   1.169   1.323
大库>=4000    可答     427   0.547   0.729   0.926   1.121
小库<1000     不可答    43   0.978   1.117   1.247   1.330
小库<1000     可答      78   0.552   0.849   1.039   1.144
```

规模效应在距离上确实存在，方向也与假设一致（库越大距离越小）：
不可答中位数 1.029 / 1.073 / 1.117，可答中位数 0.729 / 0.748 / 0.849。

**但它同等地压低了两条分布。** 关键不是绝对距离，是**可不可分**：

```
              保住 90% 可答需阈值      拦住 90% 不可答需阈值
大库 >=4000        >= 0.926                 <= 0.874      **不可分**
中库 1k-4k         >= 0.916                 <= 0.956      勉强可分（窗口 0.04）
小库 <1000         >= 1.039                 <= 0.978      **不可分**
```

三档里两档**要保住可答题所需的阈值比要拦住不可答题所需的阈值还高**——
不存在能同时做到的那个数。按档标定解决不了这件事，因为
**问题不是阈值定在哪，是两类问题的距离分布本来就重叠**。

### 顺带暴露的：现行固定下限本身是亏的

```
             编造中 best>0.99      命中中 best>0.99
大库 >=4000    22 条里 5 条          315 条里 5 条      1:1
中库 1k-4k      3 条里 0 条          117 条里 2 条      纯亏
小库 <1000      1 条里 0 条           52 条里 3 条      纯亏
合计           拦住 5              误杀 10             **2:1 亏本**
```

**注意这是模拟不是实测。** 用的是单次检索距离，而真实管线里
`_merge_retrieval` 会合并两轮结果、把距离摊小（§二十二那条稀释效应）。
所以真实效果只会**比这更弱**，方向不变。已开配对全量实测（关闭下限 vs 线上），
判据同样预先写死、且与前两臂用同一个兑换率。

### 教训

**"数据支持 X 现象"不等于"数据支持 X 方案"。**
规模效应是真的，"按规模标定阈值"是我从这个真现象里顺手推出来的方案——
中间那一步（分档之后是否变得可分）从来没验过。
只要多花 1.8 分钟量一次，就知道这个方案从一开始就不成立。

**这次没有写一行代码。** 相比之下，前面几次是先写完、跑完全量、
再被数据否掉——那是两个多小时一臂的代价。**能在设计阶段否掉的，别拖到实验阶段。**

## 二十九、过度拒答 107 条的解剖（诊断，不是改动）

§二十六量出「校验轮拒答精确率 17%」之后，这一节回答：**那些误拒到底怎么发生的。**
全部用已有数据，没有新跑模型。

### 形态高度一致

```
107 条过度拒答（可答题 707 道的 15.1%）
  死在第 2 轮 87 条 81%   第 3 轮 20 条 19%   **第 1 轮 0 条**
  stop_reason 全部同一条：「补充检索后证据仍不足，停止生成结论」
  答案形态：107/107 逐字 [NO REFERENCE FOUND]
```

**一条都不是检索闸门拦的**——全是模型在校验轮自己说"材料里没有"。
而且：

```
过度拒答的最优检索距离   中位 0.818   P90 1.040
命中的最优检索距离       中位 0.721   P90 0.904
**过度拒答里 80% 的距离 <= 0.99，检索本来是好的**
```

**检索找到了，模型不认。**

### 一个强风险因子：文风闸门

`rich = _evidence_looks_present(dists)`，即 `min(dists) <= 0.96`（`_STYLE_GATE_MAX`）。
超过它就走 `rich=False` 分支，而那个分支的注释写着
「证据看着不足时退回严格模式：**这一档实测能稳定输出 [NO REFERENCE FOUND]**」。

```
可答题分组              n      过度拒答     命中
距离 > 0.96（严格档）    53     43.4%    45.3%
距离 <= 0.96（讲解档）  619     13.2%    74.3%
                                3.3 倍
```

**跨过文风闸门的可答题，43.4% 被拒答。**

### 但这条不能写成结论，两个理由

**1. 它只解释了 23/107 = 22%。** 78% 的过度拒答发生在讲解档，与这个闸门无关。
主要体量另有来源。

**2. 3.3 倍是上界，不是效应。** 距离 > 0.96 同时意味着两件事：
「这题本来就难」和「被切到严格档」。观察数据把两者混在一起，
**分不开**。要拿到真效应，得做只切换 `_STYLE_GATE_MAX` 的配对臂——
和证据下限那一臂一样的设计。

### 下一步该测什么（按价值排序）

1. **文风闸门配对臂**：把 `_STYLE_GATE_MAX` 提到 1.1762（等于取消这道分档），
   看 53 道题的过度拒答率是否真的从 43.4% 掉下来、以及不可答题的编造涨多少。
   这是三个候选里设计最干净的一个。
2. **校验轮提示词**：78% 的误拒发生在讲解档，说明校验轮本身偏保守。
   但提示词改动没有单一开关，配对性差，得先想清楚怎么测。
3. 上面两条都做完，再回头看「17% 精确率」还剩多少。

**本轮不做**，证据下限那一臂正在跑，一次只动一个变量。

## 三十、证据下限：配对实测**保留**，而我的仿真预测是反的

### 结果

```
配对 972 题，唯一差别是 AITIC_EVIDENCE_FLOOR（0.99 vs 关闭）

收益  过度拒答 → 命中       9 条
代价  拒答正确 → 编造       7 条        采纳门槛：恢复 >= 14
中性  过度拒答 → 未命中     4 条

指标            下限开     下限关       差
精确拒答       89.6%    87.7%    -1.9pp
编造          10.4%    12.3%    +1.9pp
可答命中       72.3%    72.7%    +0.4pp
过度拒答       15.2%    14.3%    -0.9pp

合计变动 30 / 972 = 3.1%
```

**判定：保留。** 这是本轮唯一一个通过了配对检验的行为改动，
也是唯一一个"上线中且现在有实证支持"的改动。

### 我的预测是错的，而且符号都反了

跑之前基于距离分布做过一次模拟（§二十八），结论是
「拦住 5 / 误杀 10，2:1 亏本」——**即下限有害，该拿掉**。
实测出来是反的：拿掉它净亏。

**错在哪**：模拟把下限建模成「best 距离 > 0.99 就拒答」，
但真实管线里下限是**逐块**过滤，且作用在 `_merge_retrieval` **合并后**的距离上。
两者命中的根本不是同一批题。§二十二记过一次同样的教训（稀释效应），
这次我在模拟时又忘了把它算进去。

**结论：涉及多轮合并的效应，静态距离模拟不可信，必须真跑。**
1.8 分钟的模拟省不掉 2 小时的实验。

### 顺带核对了一次「编造是不是被高估了」——没有

实验臂的代价样例里，有两条长这样：

```
The term "delegate legislator" is not directly mentioned in the provided material.
The term "general revenue sharing" is not directly addressed in the provided material.
```

看着像"散文式拒答被判成编造"，如果成立，报出去的 9.3% 就该往下修。
**逐条打开看之后：不成立。** 基线 28 条编造里，6 条是这种"先声明再作答"的形态，
而这 6 条**全部在声明之后继续给出了答案**：

```
"...not directly defined in the provided material. [p.512] **从功能上看**，the material discu..."
"...not directly mentioned... However, the material discuss..."
"...does not provide specific information on the treatment options..."   ← 只否认了一部分
```

**先说"材料里没有"，再拿相邻材料当答案端出来**——这正是本项目要防的失败形态，
不是拒答。**编造 9.3% 不修，维持原样报。**

差一点就把一个对自己有利的修正写进交付材料，逐条读原文之后没有。
**凡是"重新分类之后数字变好看"的修正，必须逐条读原文，不能只看正则匹配。**

### 这也解释了放宽正则为什么必然失败

同一个铺垫句式（"X is not directly mentioned… However…"），
**在不可答题上后半截是编造，在可答题上后半截就是正确答案**。
文本形态完全一样。所以纯文本规则不可能分开它们——
§二十五当时是从结果推的，现在能从机制上说清楚了：
**分界不在铺垫句，在铺垫之后的内容有没有答到点上**，那是语义判断。

## 三十一、文风闸门：**保留**，而且我上一节的假设被自己否掉了

### 结果

```
配对 972 题，唯一差别是 AITIC_STYLE_GATE（0.96 vs 1.1762＝取消分档）

收益  过度拒答 → 命中       2 条

### 上一节的假设错了，错在量级

§二十九 的观察是：

```
距离 > 0.96 的可答题  n=53   过度拒答 43.4%

我据此估计「23/107 条过度拒答可能是闸门造成的」，同时明确标注了
**「3.3 倍是上界不是效应，距离大同时意味着题本来就难，观察数据分不开」**。

也就是说，那 3.3 倍里**混杂几乎占了全部**，闸门自身的因果贡献约等于 2 条而不是 23 条。
当时那句上界的保留意见，是 §二十九 里唯一站得住的部分；
如果当时把 43.4% 当成"闸门害的"直接改，就会撤掉一道正在拦住 12 条编造的闸门。

**教训（第二次撞上同一件事）**：观察性数据里，"风险因子"和"该干预它"是两回事。

两次都是靠**先做配对实验再动手**才没改错。

### 附带确认：过度拒答不来自闸门

「107 条全死在第 2/3 轮、80% 检索距离 <= 0.99」，可以定下来：

**过度拒答是校验轮本身的行为，不是分档策略的副作用。**

下一臂直接打校验轮的提示词：原措辞里有一句
`"do not merely repeat the first answer"`——第一轮若本来就对，

但保留"删掉无据结论"的职责（有单测锁住，防止这个改动从"少误拒"变成"少纠错"）。

## 三十二、【重要更正】对照脚本只数了一半的迁移，前面几节的判定口径全部作废

### 错在哪

`compare_widen.py` 及其派生的 `compare_floor.py` / `compare_style.py` /
`compare_verify.py` 都是这么算的：

```python
gain = [q for q in common if A[q]==过度拒答 and B[q]==命中]     # 或 编造→拒答正确
cost = [q for q in common if A[q]==拒答正确 and B[q]==编造]     # 或 命中→过度拒答
```

**每一对迁移只数了一个方向。** 反向的两格——`命中→过度拒答` 与 `编造→拒答正确`——
根本没进账。四个方向只统计了两个。

这个偏差在校验轮那一臂上直接把结论判反了：

```
脚本报：收益 35 条（过度拒答→命中），代价 6 条 → 判定"采纳"
漏掉的：命中→过度拒答 **37 条**、编造→拒答正确 9 条
同一页的聚合指标：可答命中 -1.0pp、过度拒答 +1.3pp   ← 与"采纳"直接矛盾
```

**输出里就摆着推翻自己判定的数字，我差点照着它改代码。**

### 净额重算（口径：净值 =（少的编造）×2 +（多的命中），兑换率与各臂判据一致）

```
              命中    编造   过度拒答    净值
放宽正则       -19     -11     +21       +3
拒答采纳       -13      -5      +1       -3
关闭下限        +3      +5      -6       -7
撤文风闸门      -8      +3      +6      -14
校验轮新措辞    -7      -3      +9       -1
```

### 结论怎么变

| 改动 | 原口径判定 | 净额判定 | 变没变 |
|---|---|---|---|
| 关闭证据下限 | 不采纳 | 不采纳（−7，超噪声） | 不变，更稳 |
| 撤文风闸门 | 不采纳 | 不采纳（−14，超噪声） | 不变，更稳 |
| 拒答采纳 | 不采纳 | 不采纳（−3，噪声内） | 不变，但依据变弱 |
| 校验轮新措辞 | **采纳** | **不采纳**（−1） | **判反了** |
| 放宽正则 | 「14:46，3.3:1 亏本」 | 净 +3（噪声内） | **"亏本"这个说法是错的** |

**§二十五 那句「3.3:1 亏本」必须撤回。** 它只数了 `命中→过度拒答` 46 条，
没算 `过度拒答→命中` 28 条的回补。真实净额是 −19 命中 / −11 编造，
按项目兑换率是 +3，落在跨构建噪声（约 3 条 / 972）里，**跟零分不开**。
放宽正则的正确说法不是"有害"，而是**"证不出有效，也证不出有害"**。

### 现在能站住的话只有一句

> **五个候选没有一个显示出超过噪声的净收益；
> 两个"保留现状"的判断（证据下限、文风闸门）有超过噪声的支持。**

### 附带发现：校验轮那一臂几乎是纯搅动

它改动了 **145/972 = 14.9%** 的题，净值只有 −1。
捞回 35 条过度拒答、又赔进 37 条——**多半不是同一批题**。
换句话说，改提示词措辞主要是在**换一批答错的题**，不是在减少答错。

### 教训

**1. 自己写的度量工具要先证伪一次再用。** 五个臂、四个脚本、跑了十几个小时，
全部建立在一个没验过的统计口径上。单测锁了系统行为，**没有一条锁住"对照脚本算得对不对"**。

**2. 输出里自相矛盾的两个数字，必须当场停下。** 判定行写"采纳"、
聚合行写"可答命中 −1.0pp"，这两个不可能同时对。我第一次看到时按顺序读过去了，
是复算净额才发现。**对照结果里应当强制交叉校验：净额与逐格迁移必须对得上。**

**3. 单向计数会系统性地偏向"看起来有收益"。** 因为人总是先定义"我想要的改善"，
再去数那一格。反向那格不是忘了数，是**压根没想到要数**。

## 三十三、中文覆盖扩到第二本，并因此挖出混合检索的两个真缺陷

### 建库

`data\简明世界经济史.epub` —— 59 章 / 93,692 字 / 84.1% 中文，成篇正文带章节标题。
`webui` 的 `/api/build` 只收 PDF，而 `main.py` 早有 `build_epub()`，
故写了 `build_epub_kb.py`：把 main 的产物落到 webui 的库目录并按 registry 结构登记，
**不改 main.py（指纹约束），也不改 webui 的端点**。218 块，7 秒建完。

出题 20 可答 + 10 不可答，对着**全库 218 块完整正文**逐条机器校对：
证据句逐字命中 20/20、关键词 59/59、跨领域术语零出现 10/10。

### 结果：不可答满分，可答侧暴露问题

```
不可答 10 道   精确拒答 10   编造 0
可答   20 道   命中 9   未命中 2   **过度拒答 9（45%）**
```

45% 过度拒答，而这些题的证据我刚逐字核过就在库里。逐条查检索：

```
11 条失败里 **7 条证据块根本没进 top-8**
  商人语源 / capital 语源 / bank 语源 / 复式记账法之父 / 汇票支票区别 / 中央银行 / 斡脱
剩下 4 条检出了仍拒答 → 校验轮那个 17% 精确率的老问题
```

失败形态一致：**高频词淹没特定定义块**。这本书通篇「商人」「资本」「银行」，
真正给定义的那一块排不上去；「斡脱」是低频专名，向量距离 1.081 直接没匹配上。

这正是混合检索（BM25 + 向量 + RRF）该解决的。而它**默认关闭**，这一跑没开。

### 开了混合检索之后：两个真缺陷

#### 缺陷 1：拒答一次就 500

```
main.py:1321 should_escalate → min(dists) → NoneType 与 float 比较 → TypeError
```

混合检索里纯关键词命中的块没有向量距离（`dist=None`）。
这是**同一根因的第二个出口**——第一个是 `_retrieve_selected` 的排序键，早上已修。

中文那轮之所以没崩：开混合后一道都没拒答，压根没走到这个分支；英文第一道就崩。
**`main.py` 受指纹约束不能改，故在调用侧收口**（`_usable_dists`）。
全 None 时返回空列表而不是 `[inf]`——空列表走上游"没有距离信息"的既有分支，
而 `inf` 会被当成"距离极差"，等于修崩溃时顺手改了判决。

#### 缺陷 2：中文拒答契约被整个击穿

```
中文 10 道跨领域库外题
  纯向量    精确拒答 10/10   编造 0
  混合检索  精确拒答 **0/10**  编造 **10/10**
```

根因在 `_query_terms`：英文卡了 `len>=4` 且去停用词，**中文走二元组**。
问「什么是心肌梗死的典型心电图表现？」切出 `什么/么是/是心/死的/的典/...`，
这些功能词碎片几乎命中语料里每一块；而 `_keyword_rank` 的主排序键是
**命中词数**，于是"命中 8 个垃圾二元组的块"压过"命中 1 个真正专名的块"。
关键词召回永远返回块 → 无距离 → 证据闸门与下限都判不了 → 模型看到"证据"就编。

### 修法与实测

按英文侧同样的道理：**一个词命中的块太多就没有区分度，等同停用词**。
用比例而非绝对值（"命中 50 块"在 218 块库里是停用词，在 10678 块库里可能是术语）。

```
同题配对              中文不可答      中文可答     英文不可答   英文可答
纯向量（默认路径）      拒答 10/10     命中 9/20     100%       100%
混合 不过滤            拒答 **0/10**  命中 12/20     98%        80%
混合 + 本过滤          拒答 10/10     命中 11/20     98%        80%
```

**两个混合臂在英文侧逐题相同**（同为 32/40 命中、同为 7 条过度拒答），
所以"过滤零代价"是干净的配对结论；而它把中文契约从 0/10 修回 10/10。
在混合这条路上严格更好，**故设为默认**（`AITIC_KW_DF_RATIO=0` 可关）。

### 两条必须说清的边界

**1. 英文命中 100% → 80% 是混合检索本身的代价，不是这道过滤的。**
我一度差点把它算到过滤头上——当时手上只有"纯向量 100%"和"混合+过滤 80%"两格，
缺"混合不过滤"那一格。补跑之后两个混合臂完全一致，才把归因定下来。
**这是今天第三次差点把混杂当成效应。**

**2. 那 20pp 还要打折**：那批题是**按基线命中挑选**的，只能往下掉（回归效应），
真实代价小于 20pp。**混合检索本身仍默认关闭，这一条不改。**

### 中文能力现状（两本合计）

```
不可答 20 道（两本各 10）   精确拒答 20   编造 0     ← 契约在中文下逐字成立
可答   34 道                命中 20   未命中 2   过度拒答 12
```

**中文的瓶颈是检索，不是拒答。** 拒答契约在中文下没有任何松动
（两本、20 道库外题、全部逐字输出 `[NO REFERENCE FOUND]`）；
失分全部集中在"该答的没答出来"，且已定位到高频词淹没定义块这一具体机制。

## 三十四、回归验证 + 一把真正的噪声标尺

### 目的

当天改了两处（`_usable_dists` 修 500 崩溃、`_keyword_df_max` 停用词过滤且默认开启），
两处按代码路径看都只在混合检索下生效。但"按代码路径看不变"正是本轮被打脸最多的说法，
所以跑一次完整 1007 题回归验证，开关状态与 `final_rows` 那轮逐项核对一致。

### 结果：改动干净，但翻转率是同晚重跑的 12 倍

```
逐题翻转 12 / 972 = 1.2%     （同晚连续两轮是 1 / 972 = 0.1%）
编造 28 → 25，重合率 89.3%
精确拒答 +1.1pp   可答命中 -0.4pp
```

### 先排除"是我改的"

`_usable_dists` 只在 `dists` 含 `None` 时改变行为。直接抽查默认路径：

```
58 道题 / 463 个距离 / None 0 个
```

默认路径不产生 `None`（`None` 只来自混合检索的纯关键词命中），
所以它是恒等变换；`_keyword_df_max` 又只在 `_retrieve_hybrid` 里可达，而混合默认关闭。
**两处改动都不可能造成这 12 条翻转。**

### 于是它是跨时段噪声——而这正好补上一个一直缺的量

```
同一晚连续两轮        翻转 0.1%
隔约 24 小时、
中间重启过多次服务与模型   翻转 1.2%
```

**噪声底不只随并发变化，还随"隔了多久、中间重启过什么"变化。**
§二十三 里那个 4% vs 0% 的冲突当时判为"原因不明"，这一轮给了它一个同向的旁证：
**同构建的可重复性本身就是条件量。**

更有用的是净值口径的标尺——这一轮是"什么都没改"，它的净值就是噪声本身：

```
编造 -3，命中 -3  →  净值 = (+3)x2 + (-3) = **+3**
```

### 用这把尺子重新审视五个臂

```
              净值     相对噪声 ±3
放宽正则       +3       落在噪声里
拒答采纳       -3       落在噪声里
校验轮新措辞   -1       落在噪声里
证据下限       -7       约 2 倍，偏弱但仍是现有最好证据
撤文风闸门    -14       约 4-5 倍，站得住
```

**此前用的"跨构建噪声约 3 题"是在同一晚测的，低估了。**
结论方向不变（没有一个候选值得采纳），但强度要如实下调：

> 严格说，只有"文风闸门该保留"这一条明显超出噪声。
> "证据下限该保留"是现有最好证据，但只有约 2 倍噪声，**不宜说成已证实**。

### 教训

**噪声标尺要和被测对象同条件、同时段。**
本轮先后用过三个噪声值：9%（n=23）、4%（n=100×3，条件不明）、0.1%（同晚重跑）、
1.2%（跨日重跑）。每次都以为"这次总算量准了"，每次都被下一次条件变化推翻。

正确做法不是找一个"真值"，而是**每次对照都配一个同条件的空跑臂**——
就像这一轮：什么都不改跑一遍，它的净值就是那次对照的噪声。
代价是每个结论要多跑一轮，但这是唯一能让"超出噪声"这句话有意义的做法。

## 三十五、混合检索全量：**净 +36，是本轮唯一超出噪声的正收益**；顺带纠正一次归因错误

### 结果（基线用同时段的 reg_rows，按 §三十四的教训配对）

```
配对 972 题，唯一差别是 DISTILL_HYBRID

命中     +48        过度拒答 -18
编造      +6
净值 = (-6)x2 + 48 = **+36**        （空跑臂测得的噪声是 ±3）

迁移量 211 / 972 = 21.7%
```

**判定：通过预设判据。** 这是本轮六个候选里唯一一个净收益超出噪声的。

### 它推翻了自己的子集结论，方向还相反

改动前记在 docstring 里的子集数据（英文 40 题）是「可答命中 100% → 80%」，
据此我一直倾向"混合要付英文命中的代价、应保持关闭"。
全量是反的：**多答对 48 道**。

**n=40 的子集不但估错了幅度，连符号都是错的。** 这是本轮第三次栽在小样本上
（§二十二稀释、§三十一文风闸门，加这一次）。

### 但代价在安全侧，必须一起报

```
编造 25 → 31 条，占不可答题 9.3% → 11.6%
```

净值口径下 +36 是划算的（1 条编造 = 2 条正确答案），但**这个兑换率是我定的**。
项目的立身之本是"不编造"，答辩要报的核心数字里就有编造率。
**要不要用 2.3pp 的编造率换 48 道正确答案，是产品判断，不是我该替用户拍的板。**
默认维持关闭，把数据摆给用户定。

### 顺带纠正：中文被打穿的真凶找错了

此前记录（含代码 docstring 与单测）都写着"停用词过滤把中文拒答从 0/10 修回 10/10"。
**全错。** 三条实测：

1. **过滤从未触发。** 取候选 `limit=POOL=40`，`len(ids)` 上限 40；
   218 块库的 df_max=43，`40>=43` 恒假。库大于 200 块阈值更高，
   **15 个库里 14 个都大于 200 块——这个"默认开启的保护"是死代码。**
   逐题验证：开/关过滤的关键词召回结果逐块相同。

2. **真凶是 None 距离进 `should_escalate` 抛异常。** cn2h 那一臂跑在崩溃修复之前，
   异常被吞掉后流程绕过了拒答判断。修复后真机复测：

   ```
   当前构建 + 混合检索，中文库外题 10/10 精确拒答、逐字契约全中、编造 0
   ```

   **一个"只修崩溃、不改行为"的补丁，实际上恢复了整条拒答契约。**

3. **比例阈值这个设计不可行。** 218 块库真实 df（不设 limit）标定：

   ```
   真术语   五铢 0.5%  记账 1.8%  汇票 4.1%  纸币 18.3%  工业 18.3%  殖民 18.8%
   功能词   了多 3.2%  以及 10.6%  的发 13.3%  的是 15.6%  行了 16.5%  因此 35.8%
   ```

   区间完全重叠，单一比例分不开。**不是参数没调好，是设计错了。**

已改：默认关闭、docstring 换成上面三条、单测重写。
新增一条守卫测试：若将来有人把 POOL 调大使阈值变得可达，测试会失败，
**强制那个人重新审视这个设计**，而不是让它继续静默失效。

### cn2kw 臂作废

它与默认臂、与 cn2h 都不同，说明当时确实以某个更小的比例开了过滤，
但**配置没有记录、无法重建**。数据保留归档，**不作为任何结论的依据**。

教训：**实验配置必须写进脚本或落盘，不能只存在于启动服务时的 shell 环境变量里。**
本轮所有开关都做了 envprobe 校验，唯独这一臂漏了，结果就是整臂作废。

## 三十六、混合检索的代价能不能修：两条路都试了，都不行

### 先把两侧的成色看清楚

净值 +36 是按"1 条编造 = 2 条正确答案"算的，而这个兑换率是我自己设的。
交给用户拍板之前，逐条读了原文。

**收益是真的。** 抽样的答案确实答对且带页码：

```
Clade consisting of monkeys, apes, and humans → "Anthropoids ... [p.402]"
Deep midline feature of anterior spinal cord  → "anterior median fissure [p.541]"
Define biomarker → "an individual protein uniquely produced in a diseased state"
```

50/63 只命中 1 个关键词，但读原文是对的——**判分器偏保守，不是偏松**，
所以 +48 这个数字如果有偏差，方向是低估。

**代价是系统性的词形碰撞，6/6 全部坐实：**

```
circuit courts      → circuitous movement of a bacterial cell
data structure      → 核苷酸的结构
divergent thinking  → divergent evolution
anti-dumping        → ocean dumping
majority rule       → majority of species
prior restraint     → restraint in harvesting a fishery
```

**这是对本项目最难看的一种失败**：带合法页码、读着像模像样，答的却是另一个概念。
比单纯拒答难堪得多。

### 修法一：给纯关键词块补上真实距离，再过证据下限 —— 不成立

根因看着很清楚："这些块由 BM25 召回、没有向量距离，闸门判不到"。
于是取它们的向量、与查询向量算真实距离。实测：

```
代价侧（碰撞）  关键词块距离 0.494 – 0.707
收益侧（答对）  关键词块距离 0.395 – 0.629     完全重叠，超下限(0.99)的 0 个
```

**碰撞块在向量空间里并不远。** bge-m3 看到字面重合也会给近距离——
"circuitous movement" 与 "circuit courts" 就是 0.6。一个都拦不住。

### 修法二：向量侧最优距离作闸门（关键词只许补充，不许单独构成证据）—— 也不成立

修法一的表里露出另一个信号：15 个样本上，代价侧的**向量侧**最优距离
（0.805–1.021）明显高于收益侧（0.320–0.806）。看着能分。

**但 15 个样本定不了阈值。** 用全量 921 题核对：

```
              向量侧最优距离
代价（编造）   0.805 – 1.069   中位 1.004   n=12
收益（答对）   0.320 – 1.040   中位 0.787   n=63
两轮都命中     0.226 – 1.144   中位 0.720   n=418

阈值 T     挡编造   误杀收益   误伤已命中   净值
0.90      8/12     9/63      47/418     -40
0.95      6/12     3/63      26/418     -17
0.99      6/12     2/63       8/418      +2
1.05      2/12     0/63       2/418      +2
```

**任何阈值净值都 ≤ +2，落在噪声（±3）里。**

### 这是本轮第四次栽在小样本上

```
§二十二  稀释假设     n=80 看"零误杀"     → n=484 变成 4 条，结论反转
§三十一  文风闸门     3.3 倍相关强度      → 撤掉只捞回 2 条
§三十五  混合检索     n=40 看"命中 -20pp" → 全量是 +48，**符号都反了**
§三十六  向量侧闸门   n=15 看着能分       → n=921 一片重叠
```

**四次的共同点**：小样本给出的是一个"看起来干净"的分离，而全量总是重叠。
不是运气不好——**分布的尾巴本来就需要大样本才看得见，而判据恰恰定在尾巴上。**

### 结论

**混合检索的词形碰撞编造，没有基于距离的便宜修法。** 两条路都不是"没想到办法"，
是这个信号本身分不开。要真修得动语义层（比如用模型判"这块是否真在讲问句里的概念"），
那是另一个量级的改动，且会把每题的延迟再推高一截。

所以混合的取舍**原样交给用户**：

```
开：可答命中 +48 道，过度拒答 -18 道
关：编造维持 25 条（9.3%），不引入词形碰撞这种失败形态
```

默认维持关闭。

## 三十七、中文两臂重跑在当前构建上；过度拒答 55% 已定位到"不是什么"，未定位到"是什么"

### 为什么要重跑

盘点发现**四个中文臂全部跑在旧构建上**（08-13），而当前构建恰恰改了影响中文的两处：
`_usable_dists` 崩溃修复（§三十五已证实它才是中文拒答契约的真修法）、
停用词过滤默认关闭。旧数据不能代表交付构建，重跑。

### 结果（当前构建）

```
                      默认              混合
Emacs生存指南(28块)    拒答 10/10        拒答 10/10
                      命中 12/14        命中 11/14
简明世界经济史(218块)   拒答 10/10        拒答 10/10
                      命中  9/20        命中  9/20
                      过度拒答 11       过度拒答 11
```

**两本、两个配置，库外题全部 10/10 精确拒答，零编造。** 拒答契约在中文下稳固。

**混合检索在中文侧帮不上忙**：经济史一道没多答对，Emacs 反而少答对 1 道。
也就是说 §三十五 那 +48 道收益是**纯英文的**——这对"混合要不要默认开启"是个新输入，
因为 PRD 写着「中英文都要解析」。

### 经济史 55% 过度拒答：排除了三个原因

20 道可答题里 11 道过度拒答（英文全量才 15.5%）。逐条查：

```
证据是否召回     10/11 道的人工核过的证据句就在 top-8 里
闸门是否拦下     10/11 道 拦=False（闸门放行了）
死在第几轮       全部第 2/3 轮
```

**检索没问题，闸门没问题，模型是拿着证据拒答的。** 与英文 §二十九 同一个形态，
但严重程度差 3.6 倍。

再查了一个具体假设——**接地率阈值对中文太紧**（`_GROUNDED_MIN=0.3`）：

```
              n     中位     低于 0.30
中文真实答案   38   0.571    3%
英文真实答案   75   0.636    12%
```

**不成立。** 中文不比英文更贴阈值，尾部反而更安全。

### 但这条排除有幸存者偏差，必须说明

上面 38 个中文样本全部来自**答出来了的题**——被裁掉的句子根本不在样本里
（那些题最终是拒答，没有答案文本）。所以它证明的是
"进了最终答案的中文句子不比英文差"，**不能证明"裁剪不是成因"**。

抽样确实见到裁剪杀答案的实例：

```
谁被称作"复式记账法之父"？  裁剪=7 → 7 条结论全裁光 → 拒答
银行的英文 bank 怎么来的？   裁剪=2 未判定=5 → 拒答
舍克勒是什么？              裁剪=0 未判定=0 → **模型直接拒答**
```

三道题三种成因。**要分清楚，得抓第一轮裁剪前的结论，需要加埋点。本轮没做。**

### 另一个必须记下的观察：中文跑间抖动

同样这几道题，在真机复测时"世界最早的纸币""汇票和支票"都答对了，
而全量臂里它们是过度拒答。**中文侧的跑间抖动比英文明显**，
所以 9/20 这个数字本身也带不确定性，不宜精确解读。

### 结论

**能报的**：中文拒答契约稳固（两本、两配置、40 道库外题全对，零编造），
中文问答可用但"该答不答"偏多。

**不能报的**：55% 这个数字的成因。已排除检索、闸门、接地率阈值三项，
剩下模型侧拒答与裁剪两条未分离。

**下一步该做的**（未做）：在 `_semantic_support_guard` 加一处埋点，
把裁剪前的结论与逐条判定落盘，再跑一次中文臂即可分离两条成因。

## 三十八、接管复核：中文 55% 过度拒答不是一个原因，而是两个确定性 BUG + 模型侧余量

### 先纠正 §三十七的诊断边界

§三十七把最终拒答分成「模型直接拒答」与「逐句核验裁光」两类，仍然漏了一条：
**模型已经答对，但引用格式校验先把它改成拒答，语义核验根本没有运行。**

为分清三条路径，新增 `trace_cn_support.py`，在不改生产行为的前提下记录：

- Agent 多轮选择后的、最终收口前答案；
- 实际打包给回答模型的证据块；
- 逐句核验前的 claims、核验器原始 JSON、最终 verdict 与交付答案。

原 11 条经济史过度拒答样本的首轮追踪为：2 命中、2 未命中、7 拒答。
7 条拒答中，5 条是正确答案用了短章节号后被当成伪造引用，1 条被语义核验裁光，
只有 1 条在最终收口前已经是固定拒答。此前「模型拿着证据直接拒答」概括过宽。

### BUG 1：EPUB 引用身份错误地包含整段章节标题

实际 `loc` 形如：

```
ch3:1 银币诞生于美索不达米亚
```

Web 把整串放进引用标签。模型输出稳定章节号 `[ch3:1]`，或标题只错一个字，
都会被 `_verify_citations` 判成伪造引用，随后 `_finalize_grounded_answer` 把整份答案
改成 `[NO REFERENCE FOUND]`。实测「舍克勒」「risk」「交子」「汇票/支票」等均走过此路径。

修复：Web 端 EPUB 引用只使用稳定 section id（`ch3:1`）；多库仍加 `K1:`/`K2:`，
因此不会跨库歧义。`main.py` 未改。

### BUG 2：同一 EPUB 小节的后块覆盖前块，核验器看不到回答模型看过的证据

同一小节会切成多个块，它们共享同一个 `loc`。旧行为：

```
_claim_evidence_map   同标签取第一块
_support_blocks       同标签用字典赋值，后块覆盖前块
```

「复式记账法之父」的帕乔利证据在前块，后块是阿拉伯数字内容。回答模型看过两块并答对，
语义核验器却只收到覆盖后的阿拉伯数字块，遂将 4/4 结论判为 `UNSUPPORTED` 并裁光。

修复：两条证据路径都合并**本轮已实际打包**的同标签块。没有引入检索外材料，
没有放宽 `_GROUNDED_MIN`，也没有改变 `SUPPORTED` 判据。修复后该题只裁 1 条无据铺陈，
核心答案与引用正常交付；「汇票和支票」也不再被裁光。

### BUG 3：中文 subject-first 散文拒答绕过固定 token

旧正则支持「材料中没有……」，不支持「capital 一词的语源未在材料中提及」。
后者语义上是明确拒答，却会进入逐句核验并作为普通回答交付。

修复：补齐与既有英文 subject-first 分支同等窄的中文语序，仅匹配答案开头首句中
明确的「未在材料/资料/上下文中提及、讨论、定义、说明」；归一为固定拒答 token。

### 完整中文回归（默认检索，修复后）

```

Emacs（14 可答）       命中 12 / 过拒 1 / 未中 1  命中 14 / 过拒 0 / 未中 0
经济史（20 可答）      命中  9 / 过拒 11 / 未中 0 命中 17 / 过拒 2 / 未中 1
合计（34 可答）        命中 21 / 过拒 12 / 未中 1 命中 31 / 过拒 2 / 未中 1

这是同一 54 题集的跨时段前后跑，幅度仍包含模型跑间噪声；但两个确定性 BUG 均有

## 三十九、对 Claude 对话记录做逆向复核：评测身份键与固定噪声口径仍有 BUG

### BUG 1：1007 行被 `question` 单键静默压成 972 题

六份历史对话里反复出现「1007 题全量」与「配对 972 题」并存。此前把差额当作
两臂交集变化；逐行检查后确认不是缺题，而是 16 组问题被多本教材复用：

```
原始行                         1007
唯一 question                   972
唯一 (book, question)          1007
被后写覆盖的跨书样本              35
```

典型例子：`What is a clinical psychology?` 在操作系统教材里是不可答题，
在心理学教材里是可答题；只按问题文本配对会把两个不同判定对象合成一个。
更严重的是 `fullrun2.py` / `fullrun3.py` 的断点续跑也只记 question：若某本书先跑过
同一库外题，恢复运行时可能把其他书上的该题误判为“已完成”。

修复：新增 `eval_compare.py`，统一使用规范化 `(book, question)`；复合键仍重复时
直接报错，不再“保留最后一条”。全量 runner、距离 runner、重复性脚本和配对脚本
全部接入同一身份函数。题集元数据映射对 28 字符截断书名只允许唯一前缀匹配，
仍有歧义就报错，不猜书。

### BUG 2：四个旧 `compare_*.py` 仍在执行已被 §三十二判错的单向算法

旧脚本只数一个收益格和一个代价格，漏掉反向回补；另写 `net_compare.py` 并没有
修掉旧入口，后续再次运行仍会输出错误判决。且 `net_compare.py` 又把“噪声=3题”
硬编码成跨实验常数，与 §三十四“噪声是条件量”的结论冲突。

修复：五个入口全部复用 `eval_compare.summary_pair()`：

- 打印完整迁移矩阵；
- 从两臂聚合计数计算命中/编造/过拒/正确拒答净额；
- 再从迁移矩阵独立重算，二者不一致立即报错；
- 不再硬编码噪声或自动给“采纳/不采纳”，必须另配同时段、同条件空白臂。

用历史原始 JSONL 复算：

| 臂 | 正确配对 | 命中净额 | 编造净额 | 净值 |
|---|---:|---:|---:|---:|
| 放宽拒答正则 | 1007 | -19 | -11 | +3 |
| 采纳后轮拒答 | 1007 | -13 | -5 | -3 |
| 关闭证据下限 | 1007 | +3 | +5 | -7 |
| 撤文风闸门 | 1007 | -8 | +3 | -14 |
| 校验轮新措辞 | 1007 | -7 | -3 | -1 |
| 开混合检索（同时段 reg 基线） | 1007 | +48 | +6 | +36 |

净额与 §三十二/§三十五用原始行重算的结果一致，因此**决策方向未改变**；
修正的是样本身份、分母与工具的未来可靠性。重复性分母改为 1007：
可答 707、不可答 300、类别翻转 1、作答/拒答翻转 0、答案文本不同 4。

### BUG 3：产品接口仍向用户展示已经被推翻的固定噪声范围

`/api/compare` 返回体仍写“同配置重跑翻转 0.6–1.5%”，但后续同一项目测到
0.1%、1.2%、4% 和 9% 等不同条件值，且成因没有被证实。这个固定范围会让用户
把单题 A/B 当成统计证据。

修复后只陈述可证实边界：单题一次对照不构成统计结论；批量实验要同题配对，
并同时跑同条件、同时段空白对照。不再展示固定噪声数字，也不把差异归因为 GPU。

### 对旧“零同标签碰撞”结论的纠正

历史记录曾用 39 次检索、312 个块观察到零碰撞，便把
`_claim_evidence_map(... setdefault ...)` 判为非缺陷。该样本没有覆盖后来加入的 EPUB：
EPUB 一个 section 会切成多块且共享 `loc`，实际在经济史库稳定复现同标签碰撞，
并导致核验器看不到回答模型看过的帕乔利证据。§三十八的修复与回归测试有效；
旧结论只能表述为“当时所测 PDF 样本未观察到”，不能外推为全格式安全。

## 四十、纠正混合检索距离门控：关键词只可补强向量证据，不可独立救活问题

### 旧结论为什么失效

§三十六曾用 `dist_full.jsonl` 判断“没有一个便宜的距离阈值能消除混合检索新增编造”。
本轮复核确认该文件的题目元数据同样按 `question` 单键回填：跨教材复用的问题会被
错误地绑定到第一本书，35 行的教材身份因此不可靠。更换为复合键后重新采集首轮纯向量
距离，得到 `dist_full_v2.jsonl`：1007 行、1007 个唯一 `(book, question)`，旧文件保留
作为错误历史，不覆盖。

正确的产品策略也不是“距离超过阈值就把混合答案一律拒掉”，而是：

```
纯向量最优距离 > 现有证据下限 0.99  → 不运行关键词召回，保持纯向量路径
纯向量最优距离 <= 0.99              → 允许关键词结果用 RRF 补强
```

这样关键词不能靠词形碰撞独立救活一个向量侧本来无证据的问题；向量证据合格时，
关键词仍可补回术语、专名和精确词面。

### 1007 题历史双臂回放

把正确首轮距离与同题默认臂、混合臂按复合键配对，按上述实际分流回放：

| 距离上限 T | 相对纯向量命中 | 相对纯向量编造 | 退回纯向量 | 净值 |
|---:|---:|---:|---:|---:|
| 0.85 | +34 | +0 | 466 | +34 |
| 0.90 | +36 | +2 | 368 | +32 |
| 0.93 | +43 | +1 | 328 | +41 |
| 0.95 | +45 | +4 | 310 | +37 |
| **0.99** | **+48** | **+2** | **260** | **+44** |
| 1.05 | +48 | +4 | 194 | +40 |

无条件混合为命中 +48、编造 +6、净值 +36；0.99 分流保留全部命中增量，少引入
4 条编造。按教材留一选择阈值时，11/12 本选择 0.99、1/12 本选择 0.93；留出教材

### 实现与证据边界

`_retrieve_hybrid` 现在先做纯向量检索；若 `_evidence_floor_blocks(dists)` 为真，直接
返回纯向量结果，不再调用关键词路径。它复用线上已有的 `_EVIDENCE_FLOOR = 0.99`，
没有新增阈值；缺距离时保持原行为；关键词路径异常仍静默退回纯向量。

混合检索仍然**默认关闭**，本改动只让用户显式打开它时更安全。上述数字来自同一批
历史默认/混合生成结果的确定性分流回放并做了按教材留一检查，不是修复后重新生成的
第三条 1007 题全量臂；因此它足以推翻旧的“距离完全无用”结论并支持机制修复，
但不能冒充新的线上编造率点估计。正式改默认仍需同时段空白对照。

### 本轮代码审计继续发现的边界缺陷

1. `_hybrid_enabled("false")` 原来因 `bool("false")` 得到 True；现统一显式解析字符串。
   同类问题也修到反馈记录的 `abstained` 和本地建库的 `use_vl`。
2. `/api/questions`、`/api/retrieve`、反馈轮数和本地建库参数遇到非法数字会抛 500；现统一

3. 多库问答中单库运行时检索失败原来会被静默跳过，最后仍用其余书作答，形成“选了 A+B，
   实际只查 B”的隐性不完整结果；现明确停止本次多库回答并指出失败库。
4. 多库混合检索和页范围检索都会对同一个问题按书重复算 embedding；后者甚至先在循环外
   算一次、再每库各算一次。现把循环外已经得到的 query vector 传入每个库，选 4 本书仍
   只嵌入一次，不改变排序或判据。
5. 最新 8011 真机检查：16 个库加载；`hybrid="false"` + 非法 `limit` 的 `/api/retrieve`
   返回 `retrieval=vector`、`llm_called=false`；无头 Edge 审计未发现控制台/HTTP 错误，
   问答主控件和混合开关可见，页面无横向溢出。
6. 资料文件名/错误信息会进入资料按钮的 `title` 属性，旧代码错误地使用正文转义；带引号
   的上传文件名可能破坏属性边界。所有动态 `title`、`data-*`、`option value` 已改用
   `escapeAttr`，并加入静态守卫。答案正文仍保持“先全文转义、再还原少量白名单格式”。
7. 上传依赖探测改用 `python_multipart` 官方模块名，移除旧 `multipart` 别名的弃用警告。
8. `fullrun3.py` 原来把一次瞬时网络失败写成“请求失败”后，断点恢复会把它永久视为已完成；
   500 若返回非 JSON 还可能中止整条全量。现对网络/5xx 做最多 3 次有限重试、稳健解析错误体，
   恢复运行时明确重跑失败行，不让环境故障进入模型指标分母。
9. 当前条件混合臂的 300 道不可答题先跑完后，发现 4 条答案开头已明确写出 “The term …
   is not directly defined in the provided material” 或 “The material does not specifically
   mention …”，却因旧窄正则不认识而当作编造交付。历史 9 条完整臂扫描表明，这两个**精确
   开头**只命中过编造/未命中，没有命中过默认臂正确答案；现只收口这两型，不复活已经被
   n=1007 否决的任意 `X is not directly ...` 宽规则。当前原始回包可确定性纠正 4 条。
10. 批量自检内部用同一个 `miss` 表示“可答题未命中”和“不可答探针误答”，汇总时又把所有
    miss 放进人工 GT 命中率分母，导致一次编造同时扣两个指标。现分别计算
    `answerable_miss` / `probe_answered`；命中率和拒答率不再互相污染。
11. `fullrun2.py`、`fullrun3.py`、`dist_full.py` 把 Beta 绝对路径写死；换 checkout 运行时
    可能形成“代码来自 A、题集来自 B”的静默串库。三个持续使用的 runner 现从自身位置推导
    项目根目录，并由测试禁止重新引入 `E:\Ollama_test_beta`。历史一次性取证脚本不改写。
12. `/api/status` 原来不返回混合默认、证据下限、文风闸门与拒答实验开关，评测产物只能
    从启动命令或 tag 猜实际配置。现返回有效配置并加入真调用测试；测试还当场抓住并修正了
    一个不存在的停用词常量引用，避免状态接口因“自证字段”新增 500。
13. `/api/ask` 与本地路径建库仍直接对 JSON 值调用 `.strip()`；数组/数字输入会抛
    `AttributeError` 变成 500。现先验证文本类型并返回 400，不让客户端格式错误伪装成服务故障。
14. 教材外补充与混合检索在非流式、GET 流式、POST 流式各自有一套字符串布尔解析；
    `extend="no"` 会在部分路径被当成开启，`hybrid="yes"` 又只在部分路径生效。现全部复用
    `_coerce_bool`，测试锁住 POST 转发后的 `extend=0 / hybrid=1`。
15. `/api/brief` 仍会对非文本主题直接 `.strip()` 形成 500；同类隐患还存在于问题生成、
    概念对照、A/B、仅检索、POST 流式和反馈入口。现在这些入口在执行检索/生成前统一返回
    400；反馈的 `sources` 若不是数组也不再因迭代数字而 500。
16. 上传文件保存成功、后台建库任务接管前若发生任务冲突或异常，旧代码只在 `ValueError`
    分支删 PDF，其余分支会留下孤儿文件和 UUID 目录。现在所有未接管失败路径都调用同一清理
    函数；函数只允许删除 `uploads` 根下的目标文件和直属空目录，不递归、拒绝根外路径。
17. 批量评分仍会把 JSON 字符串 `answerable="false"` 当真值，并把字符串
    `keywords="recursion"` 逐字符遍历；前者污染可答/不可答分母，后者会因命中任一字母产生
    假命中。现复用 `_coerce_bool`，字符串关键词作为一个完整短语，汇总行保存规范化布尔值。
18. 正式 runner 过去只把连接状态 0 视为请求失败；HTTP 4xx/5xx 会被算成编造或未命中，
    并在续跑时永久跳过。现在只有 2xx 进入评分；续跑前原子剔除失败/损坏行，成功键重复立即
    报错，避免重试成功后同题双计。`fullrun3.py` 新增显式 `auto/on/off` hybrid 参数及
    `<tag>_manifest.json`，续跑配置不同则拒绝把两个构建混进同一结果文件。

当前完整单测：**391 passed，1 个 ChromaDB 第三方弃用警告**。`data/main.py` 与稳定目录 SHA-256
仍同为 `FE179DB3...52C4`，项目汇报的 CLI 自证路径未被改写。

## 四十三、【更正 §三十六】"距离修不了词形碰撞"是错的——我把机制建模错了

### 结论撤回

§三十六 写着：

> **混合检索的词形碰撞编造，没有基于距离的便宜修法。**
> 两条路都不是"没想到办法"，是这个信号本身分不开。

**这句话是错的，撤回。** 错因不在数据，在我对机制的建模。

### 错在哪

我当时算的是：**闸门拦下 → 该题变成过度拒答**。
于是把 444 道"两臂都命中"的题算进误伤——因为它们的向量距离超过阈值，
按我的模型会被拦成拒答。这样一算，任何阈值净值都 ≤ +2，落在噪声里。

但实际要实现的机制是：**闸门拦下 → 退回纯向量结果**（关键词只能补强，
不能独立救活问题）。两臂都命中的题退回后**仍然是命中，零损失**。

我把一个"限制加分项"的机制，建模成了"一票否决"。两者的代价侧差 444 道题。

### 按正确语义重算（我独立实现，未复用他人代码）

```
阈值T     命中Δ    编造Δ    净值
0.93     +43      +1      +41
0.95     +45      +4      +37
0.99     +48      +2      **+44**
1.05     +48      +4      +40
纯混合    +48      +6      +36
```

**0.99 保住全部 48 道命中，同时把新增编造从 6 条压到 2 条。**
且 0.99 不是新调的参数——它就是既有的 `_EVIDENCE_FLOOR`，不引入拟合阈值。

按教材留一法（更严谨，避免同书泄漏）：命中 +46、编造 +3、净值 +40。
我另做的随机半分留一法中位 +36、范围 +2~+50——**随机分割会让同书的题互相泄漏，
是较差的设计**，以按教材那版为准。

### 教训：机制建模错了，数据再干净也没用

§二十八 到 §三十六 我连着五次用"先量再改"否掉候选方案，方法本身是对的。
但这一次量的是**一个我想象出来的机制**——测量再精确，测的不是要实现的那个东西。

**下次量一个改动之前，先写出它落地后的伪代码，确认测量模型与它逐行对应。**
这条比"先量再改"更靠前：量错对象，比不量更危险，因为它会给出一个看起来严谨的错误结论。

## 四十五、同时段 A/A/B：本轮唯一方法上站得住的对照，结论与此前全部相反

### 为什么必须重做

此前六次对照的共同软肋：**噪声标尺不是同时段测的**。§三十四 已写明该怎么做，
但此后仍反复引用别时段的 ±3。Codex 指出这一点，成立。
本次用整段独占机器的时间补上：**A1 → B → A2**，两个空跑臂把实验臂夹在中间。

判据在跑之前写死并落进 `aab_analyze.py`（见 `PLAN_weekend.md`），跑完不许改。

### 结果

```
A1 空跑臂    命中 535/707 = 75.7%   编造 26/300 = 8.7%   过度拒答 87
A2 空跑臂    命中 536/707 = 75.8%   编造 24/300 = 8.0%   过度拒答 89
B  混合+闸门 命中 584/707 = 82.6%   编造 19/300 = 6.3%   过度拒答 68

A1 ↔ A2：逐题翻转 8/1007 = 0.8%，净值 +5   → **同时段噪声 N = 5**
A1 → B ：逐题翻转 173/1007 = 17.2%，净值 **+63**
A2 → B ：逐题翻转 172/1007 = 17.1%，净值 **+58**
```

三条判据：

```
① 两臂净值都 > 3N（=15）        +63 / +58   过
② 编造绝对增加 <= 5             实际 **-5**（减少）  过   ← **这一行是错的，见下**
③ 中文四本 40/40 拒答、编造 0    两配置均满足        过
```

> ## 【2026-08-16 更正：判据②判错了，正确结论是「不采纳」】
>
> **判据②的实现与它自己的文字相反。** 计划书里写的是
> 「编造**绝对条数增加** <= 5」，并明说这是独立否决项、
> **不许用净值掩盖新增的危险失败**；但 `aab_analyze.py` 里实现成了
> `max(df1, df2) <= 5`，而 `df` 是**净额**。
> 净额口径下「新增 50 条、修好 60 条」会算成 −10 通过，
> 而用户实际会多撞上 50 个新失败——与原意正相反。
>
> 这与 §三十二 记录的单向/净额混淆是同一类错误，而且更糟：
> **那次是工具没想到，这次是我写下了正确原则、又亲手把它实现成反面。**
>
> 按原意重算：
>
> ```
> 新增编造   B-A1 = 5    B-A2 = 6    取最差 6 > 5   → **② 不过**
> （修好 12 / 11 条；配对精确检验 p = 0.143 / 0.332）
> ```
>
> **因此正确判定是：维持默认关闭。**
>
> 另外，「编造减少」这个说法本身也没有统计证据——
> 5 vs 12、6 vs 11 这种量级，配对精确检验 p = 0.143 / 0.332 / 0.210，
> 只能说「本次点估计偏低」，不能说安全性改善了。
> **而命中提升是有强证据的：p = 5.1e-5 / 6.9e-5。**
> 正确的一句话是：**英文召回收益成立，安全侧既没有改善证据、也没有恶化证据。**

### 三个与此前相反的发现

**1. 编造是减少的，不是增加的。** 此前三次跨时段测量分别给出 +6 / +3 / +5，
本次同时段给出 **−5 到 −7**。跨时段对照把符号搞反了。

**2. 词形碰撞不是混合引入的。** 以两个空跑臂一致的结果为准：
B 新增编造 5 条、修好 11 条。而空跑臂（纯向量）自己编的那些是：

```
Define voter fatigue        → 答成"员工被顾客置于困境"
Define conditioned response → 答成法律上的 condition
dominant allele             → 答成 dominant factor（交易主旨）
```

**纯向量自己也在做同类概念混淆，而且更多。**

**3. 我反对的核心理由站不住。** 我此前只数了混合臂**新增**的编造，
没去看纯向量臂自己编了什么——又一次单向计数（§三十二 同型错误）。

### 但仍要记下的两点保留

**演示三题：默认配置在其中一道上更好。**

```
              默认              混合+闸门
Dreams        引用 6 处 可信度中  引用 1 处 可信度低
```

聚合偏向混合，但现场要展示的具体三道里有一道默认更好看。n=1，也可能是抖动。

**中文没有收益。** 两配置命中率完全相同（59/64 = 92.2%），
拒答契约都是 40/40、零编造。混合对中文是**无害也无益**。

### 顺带测出的一个题集问题（影响该怎么报数字）

按题型拆开 A1：

```
answerable   n=497  命中 85.5%   过度拒答  9.9%
fuzzy_desc   n=103  命中 81.6%   过度拒答  3.9%
fuzzy_kw     n=110  命中 21.8%   过度拒答 30.9%
──────────────────────────────────────────────
含 fuzzy_kw   75.1%      剔除 fuzzy_kw  84.8%
```

`fuzzy_kw` 是"从定义里抽 3 个词拼成的串"，例如
`preponderance sarah indeed`、`invited stanley clark`——**不是问句**。
系统拒答它是正确行为，却被计成"该答没答"。

**这 110 道同时压低命中率约 10pp、抬高过度拒答约 3–4pp，属题集构造，不是系统能力。**
它不影响任何 A/B 结论（各臂同题集），也不影响编造率（只在不可答题上算）。
但报"可答命中"这个数字时必须分开说。

### 方法论

**这次的价值不在结论，在于它是第一个方法上站得住的对照。**
同一个改动，跨时段测出"编造 +6、该保持关闭"，同时段测出"编造 −5、三条判据全过"。
差别不在数据量（都是 1007 题），在**有没有同时段空跑臂**。

一次零改动的重跑（cleanbase vs aa1，同配置不同时段）净值就有 **+5**——
这是"±3 常数"被直接证伪的实物反例。`net_compare.py` 已改为**不再自行判定**，
只出数字，判定必须由带空跑臂的 `aab_analyze.py` 做。
