## 1. 并发注册表写入缺陷

- 真机复现：240 次多库检索与 100 次活动库切换并发时，切库 8 次返回
  Windows `WinError 5`，失败点为 `registry.json.tmp -> registry.json`。
- 根因：原子写使用固定 `.tmp` 文件，且 helper 本身没有收口所有读锁；
  Windows 上另一读者/安全软件短暂持有目标时，`os.replace` 也可返回
  `PermissionError`。
- 修复：读写 helper 统一进 `_state_lock`；每次写使用 PID + UUID 唯一临时文件；
  仅对 `PermissionError` 做 5 次有界退避；其他错误仍立即暴露；残留临时文件在
  `finally` 中清理。
- 复测：240/240 检索成功、100/100 切库成功，串库 0、空来源 0、非 200 为 0；
  p50 236 ms、p95 404 ms、max 501 ms，结束后活动库恢复正确。

## 13. 深测续跑发现并修复的产品缺陷

### 13.1 反馈闭环

- 反馈读取与追加共用同一锁，读者不再可能看到半行 JSONL；反馈与回归运行追加后
  `flush + fsync`，降低崩溃/掉电丢记录风险；回归历史读取会跳过残缺末行。
- 失败样本身份从仅 `question` 改为 `(question, sorted library set)`，并只采用同身份最新
  反馈；同一道题在不同教材不会互相覆盖。
- 问题与答案不再静默截断：问题完整保存至 4000 字符、答案至 20000；超限在写盘和
  调模型前明确 400。

### 13.2 多库检索与概念对照

- 第二/三轮检索原来只按正文去重，两个库含相同文字时会静默删掉其中一个库的证据；
  现按 `(library identity, text)` 去重，同库重复仍合并、跨库同文保留。
- 真实三库混合检索返回 7 个来源、覆盖全部三库且无 500；真实三库深问答覆盖全部三库，
  两轮、引用校验通过，并裁掉 1 条无支持结论。
- 概念对照原按显示名作字典键，同名教材会覆盖；现按 library id 计算，同名时展示
  `name · id` 消歧，唯一名称保持原样。

### 13.3 批量和评测完整性

- `/api/batch` 过去会在混合有效/无效项目中静默丢掉坏项目；现先验证整批，第 N 题错误
  就整批 400，模型尚未调用。
- 配对 runner 完成时验证复合键与计划完全相等、无失败/重复/畸形行，并记录结果哈希、
  结束服务/库/源码身份；manifest 原子写盘并 `fsync`。
- analyzer 验证行哈希、首尾身份、引用失败、重复引用与同臂跨遍翻转；自身也记录哈希，
  完整性失败时以非零状态退出。
