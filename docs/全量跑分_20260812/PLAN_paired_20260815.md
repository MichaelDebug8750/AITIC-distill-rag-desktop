# 2026-08-15 长时逐题配对实验（运行前冻结）

## 目的

判定“条件混合检索是否应成为全局默认”。本轮不再用不同时段的整臂结果相减，而让同一道题的
`hybrid=false` 与 `hybrid=true` 请求相邻执行；两遍重复时反转题目顺序和 A/B 先后，平衡时间漂移。

## 冻结规则

- 实验开始后不修改 `webui.py`、`webui_index.html`、`main.py`、题集、知识库或模型配置。
- 每次请求都显式携带 `hybrid`，不依赖服务默认值或启动 shell 环境。
- manifest 必须记录 `/api/status`、知识库清单、题集/跑分器/四个核心源码 SHA-256、Python 版本、
  顺序种子和预期题数；恢复运行时不一致就拒绝续跑。
- 结果按 `(pass, book, question, arm)` 唯一；非 2xx、请求失败或重复键不进入正式判定。

## 运行顺序

- 英文：1007 题 × A/B × 2 遍，共 4028 次请求。
- 第 1 遍：固定种子打乱题序；每题 A/B 先后由题目标识确定。
- 第 2 遍：题序完全反转，每题 A/B 先后也反转。
- 中文：104 题使用同样协议，至少 1 遍；时间允许则 2 遍。
- 演示题必须在请求体显式传 `hybrid=false/true` 并保存完整回包；只作现场质量检查，不用 n=1
  替代全量指标。

## 预注册判据

### 1. 英文召回收益

两遍都必须满足：混合命中净增 > 0，且命中/非命中的配对精确检验 `p < 0.01`。

### 2. 不可答安全（独立否决项）

以下任一出现就不设为全局默认：

- 任一遍混合编造总数高于纯向量；
- 存在同一道题在两遍中都表现为“纯向量不编造、混合编造”（持续性新增编造）；
- 人工复核发现持续性新增编造属于答错概念、库外常识作答或带合法页码的错误答案。

“新增 N 条、修复 M 条”必须分开报告；不得用净额隐藏新失败。编造差异同时报告 McNemar
精确 `p`，没有显著性时只能写“点估计”，不能写“安全改善成立”。

### 3. 中文硬门槛

每遍、每配置均须 40/40 精确拒答、编造 0；并逐题报告迁移，不能因总命中相同就称“无影响”。
若混合命中低于纯向量，默认不开。

### 4. 决策

- 三项全部通过后，才进入“可考虑默认开启”，仍需结合演示题和稳定汇报口径人工拍板。
- 任一项不通过：维持默认关闭，保留显式开关；只在能提出确定性、可单测且不牺牲拒答安全的
  修法时优化，否则如实结论，不为追指标继续调参。
