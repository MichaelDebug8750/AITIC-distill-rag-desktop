## 二、本轮最有价值的发现

**语料规模同时抬高召回与幻觉**，两轮独立数据同向、三档单调：

| 分组 | 可答命中 | 编造率 |
|---|---|---|
| 大库 ≥4000 块 | 73.8% | **15.5%** |
| 中库 1000–4000 | 70.1% | 3.7% |
| 小库 <1000 | 72.0% | **0.0%** |

机制：块越多 → 检索总能找到语义相近的内容 → 该答的题证据更足，
不该答的题也「看起来有据」。检索距离分布证实了这一点：不可答题的最优距离
中位数随库增大而下降（小库 1.142 → 大库 1.034），落在旧闸门 1.1762 之内的
比例从 64% 涨到 88%。

**结论：拒答闸门必须随语料规模标定，固定阈值不可移植。**

## 四·五、天亮前挖出的一个真缺陷（**尚未修复，已定位**）

**校验轮的拒答被当成「降级」丢掉了。** 这是**当前构建里就有的**问题，不是实验产物。

```python
_round_is_clean():   if M.is_abstain(answer): return False   # 拒答永远"不干净"
_adopt_next_round(): 上一轮干净 → 新一轮必须也"干净"才采纳   # 于是拒答被拒绝
```

成立的路径：

```
第一轮  给出带合法页码的答案（引用命中、正面作答）→ 判定"干净"
第二轮  查完证据认定材料里没有 → 拒答
采纳规则  上一轮干净、这一轮"不干净" → 不采纳，保留第一轮
结果    **正确的拒答被扔掉，编造被保留**
```

「上一轮干净」只说明它引用命中、正面作答，**不代表它对**。不可答题上第一轮
编得有模有样恰恰最危险——v7 的 49 条幻觉审计里 42 条都带合法引用。
这条规则等于**把校验轮对不可答题的纠错能力关掉了**，而那正是「全做 AGENT」
这个决定的主要卖点。

**它是我自己加的**（「7 处修复」之一，为防校验轮把好答案顶掉）。方向对，
但把「拒答」和「更差的答案」混为一谈了。

**没有当场改**，挂开关跑了 n=1007 配对全量。**结果是：按它修反而更糟。**

```
收益  编造 → 拒答正确       8 条
代价  命中 → 过度拒答      39 条     判据上限 4 条  → 不采纳
```

**1:5 亏本。** 而这个数字顺带量出了一件更要紧的事：

```
第二轮拒答被采纳的场合共 47 次
  拦对了（本来是编造）      8 次
  拦错了（本来答得对）     39 次
校验轮拒答的精确率 = 8/47 ≈ 17%
```

**校验轮说「材料里没有」，83% 的概率是它自己没找着。**
所以 `_round_is_clean` 丢弃拒答这件事，**逻辑上错，效果上对**——
它挡掉的 39 条误杀远多于放过的 8 条编造。歪打正着。

**顺带更正一条我之前说错的**：我曾把 3 条「拒答正确→编造」的反向迁移归因于
这个缺陷。交叉检查否掉了——采纳臂里这条机制是**关掉的**，那几道题照样翻。
它们是贴着判决边界的题，任何扰动都会翻面。**机制存在（有单测），
但它不是那几条的成因。**

**真正该改的不是采纳规则，是校验轮为什么在有据可查的题上说没有。**
那是检索或提示词的问题。本轮不做，已记进 §二十六。

## 五、方法论教训（都是这轮踩出来的）

1. **改动影响模型输出分布时，不能用存量数据验证。**
   用 60 条旧答案验出「零误杀」，真机跑出来 15%——旧答案由旧代码生成。

2. **噪声底是条件量，不是常数。** 我先测得 4%（100 题×3 次），用它否掉了好几个改动；
   后来两轮全量实测同一指标是 **0.0%（0/972），答案 99.6% 逐字相同**。
   两者差 40 倍，我至今没有验证过的解释（最可信的候选是测量时的并发 GPU 负载，
   批式推理对 batch 组成不是数值不变的——**但这是假设，没测**）。
   引用噪声底必须连测量条件一起引，否则「我量过了」比没量更危险。

6. **捆绑回退会连累无辜的那一半。** 放宽正则和铺垫补丁一起上、一起撤，
   数据只能说「这一对不行」，说不出是谁的问题。结果是用 B 的罪证判了 A 的刑。

7. **写进注释和单测的错误结论最难纠。** 那条错误归因被我同时写进代码注释、
   函数 docstring 和一个单测类文档，三处互相印证，看着像有据可查的定论。
   结论写得越正式，后面越没人回去查它的原始数据。

3. **小样本会系统性高估改动价值。** 稀释假设第一次测时对照组 80 条，
   得到「多拦 4 条、零误杀」；扩到 484 条后误杀变成 4 条，结论反转。
   **误杀是小概率事件，小样本大概率一条都抽不到**，而收益侧容易估准——
   这种不对称让人高估价值。以后凡是「收益明显、代价为零」，先问代价侧样本量够不够。

4. **判据要在看数据之前写死。** 否则总能为想留的改动找到理由。
   这条今晚兑现了一次：放宽正则的重测判据写进脚本时还没有数据，
   跑完是 14:46，**只看头部指标（精确拒答 +4.1pp、编造 −4.1pp）会拍板通过**，
   代价藏在可答命中 −2.7pp 里，而且必须逐题配对才看得出交换比。

8. **自己加的防护规则要按「新增风险」对待，不能按「修复」对待。**
   `_adopt_next_round` 是作为 BUG 修复混在 7 处修复里上线的，没单独测过代价侧。
   它修好了要修的问题，同时开了一个新洞（见 §四·五）。
   凡是「加一条规则来阻止某种情况」，都要问：**它会不会把正确的情况也拦掉？**

5. **先量再改。** 怀疑「同页多块撞标签压低接地率」时先测了一把：
   39 次检索 312 个块，**零撞标签**。若按直觉去改，就会在不存在的问题上
   动核验链路。

## 六、悬而未决（需要你拍板）

1. **可信度 76% 是「低」** —— 628 条可作答答案里 低 478 / 中 137 / 高 13。
   根因：**2653 个句子里只有 32% 带引用**，其余进逐句核验判不出来。
   提示词压不动（试过，60%→56%）。

   **分层呈现能买到多少，我算了**（判据：只按「有引用的句子」算，≥2 句可溯源即中/高）：

   ```
   每条答案里有引用的句子   0 句 140 条 (22.3%)   1 句 242 条 (38.5%)
                          2 句 157 条 (25.0%)   ≥3 句  89 条 (14.2%)

   分层后：可升到中/高 246/628 = 39.2%
           仍然是低    382/628 = 60.8%
   ```

   **即「低」从 76% 降到 61%，买到 15pp，不是翻盘。** 而且 22.3% 的答案
   **一句带引用的都没有**，那些本来就该是低，不该靠改口径洗白。
   我的判断：**这不是显示问题，是模型引用密度不够**。真要动，该往「让模型
   多标引用」使劲，而不是换个算法把低的说成中的。**要不要做，你拍板。**

2. **中文能力：专项已经补齐，不再停在 24 题小样本。** 四本中文教材当前默认配置合计
   可答命中 61/64（95.3%）、不可答精确拒答 40/40、编造 0。该专项仍只代表人工校对的
   中文题集，不与 4432 题 CLI 汇报指标混算。条件混合在中文侧没有净增命中，因此不能用
   英文收益外推成“中英文都受益”。

3. **混合是否默认开启仍是产品决定。** 同构建原始回包为命中 +51、编造 +3；统一回放
   当前确定性拒答规则为命中 +51、编造 +1。收益成立，但残余失败含术语碰撞与库外常识，
   且中文无净收益。本轮保持 `hybrid_default=false`，没有用净值替用户改安全优先级。
